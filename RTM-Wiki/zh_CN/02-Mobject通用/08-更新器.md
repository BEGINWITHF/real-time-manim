# 更新器：Mobject 上的方法

给对象挂上「每帧执行」的函数：跟随、累积运动、实时读数。

## 参数

### add_updater

```python
def add_updater(update_function: _Updater, index: int | None = None,
                call_updater: bool = False) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `update_function` | 可调用 | — | `f(mob)` 为非时间型每帧一次；`f(mob, dt)` 为时间型，`dt` 为距上一帧的秒数 |
| `index` | `int` 或 `None` | `None` | 插入位置；`None` 追加末尾（决定执行顺序） |
| `call_updater` | `bool` | `False` | `True` 时挂载后立刻先执行一次（`dt=0`） |

> **返回**：自身。**带 updater 的对象必须 `self.add(...)` 进场景才会被驱动**（`ValueTracker` 也一样，见 [10-ValueTracker](10-ValueTracker.md)）。动画期间 updater 照常执行。

#### 样例：时间型与非时间型

旋转方块挂时间型 updater（`f(mob, dt)`），标签挂两个非时间型——一个每帧读宽度写数字、一个用 `index=0, call_updater=True` 立即贴到方块下方并全程跟随。

```python
from real_time_manim import Scene, Square, DecimalNumber, \
    BLUE, YELLOW, UP, DOWN, LEFT, RIGHT, DEGREES, FadeIn
from real_time_manim.vulkan_bind import MLWindow, Wait

class AddUpdaterDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        sq = Square(color=BLUE, side_length=1.0, fill_opacity=0.6).shift(LEFT * 3.5)   #蓝色方块
        self.add(sq)   #进场景（带 updater 的对象必须进场景才会被驱动）
        spin = lambda m, dt: m.rotate(dt * 90 * DEGREES)   #时间型 f(mob, dt)：每秒转 90°
        sq.add_updater(spin)   #挂上更新器
        lbl = DecimalNumber(0, num_decimal_places=2, color=YELLOW).scale(0.7).shift(LEFT * 3.5 + DOWN * 1.6)   #读数标签
        val = lambda d: d.set_value(round(float(sq.get_width()), 2))   #非时间型 f(mob)：每帧读方块包围盒宽度
        pos = lambda d: d.next_to(sq, DOWN, buff=0.3)   #非时间型：标签跟着方块走
        lbl.add_updater(val)   #默认追加到列表末尾
        lbl.add_updater(pos, index=0, call_updater=True)   #插到开头，且挂载时立即执行一次
        self.add(lbl)   #标签进场景
        win.play(Wait(1.0))   #停留 1 秒：方块持续旋转、数字持续刷新
        win.play(sq.animate.shift(RIGHT * 2.0), run_time=0.5)   #动画期间 updater 照常驱动
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：蓝方块挂了一个**时间型** updater——`f(mob, dt)`，每帧转 `dt × 90°`（一秒正好 90°），在 1 秒的 `Wait` 里肉眼可见地匀速旋转；旋转时它的包围盒宽度不断变化，下方的黄色数字标签（两个**非时间型** updater）实时显示这个宽度、并贴着方块底部跟随。`index=0` 把位置 updater 插到执行列表开头、`call_updater=True` 让它挂载瞬间就摆好位置。最后一段 `animate.shift` 动画期间，旋转和读数照常进行。

<video src="assets/RTM output/08-更新器-add_updater.mp4" controls width="560"></video>

> 提醒：非时间型 updater **别在参数里缓存值**——`d.next_to(sq, UP, buff=0.3)` 这种每次都重新取 `sq` 位置的写法才跟得住；`always.next_to` 语法糖同理。对象忘了 `self.add` 是最常见的「updater 不动」原因。

### remove_updater / clear_updaters

```python
def remove_updater(update_function: _Updater) -> Self
def clear_updaters(recursive: bool = True) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `update_function` | 可调用 | — | 传的是**同一个函数对象**（用变量把函数存住） |
| `recursive` | `bool` | `True` | 仅 `clear_updaters`：是否连同所有子对象一起清 |

> **返回**：自身。`remove_updater` 按引用移除**一个**；`clear_updaters` 清空全部（重复挂载了同一个函数也会全部移除）。

#### 样例：挂、移除、再挂、清空

命名保存的 `spin` 挂上去转，`remove_updater(spin)` 按同一函数对象摘掉；换匿名函数下落，最后 `clear_updaters()` 一键全清——每次数量打印验证。

```python
from real_time_manim import Scene, Square, \
    GREEN, DOWN, LEFT, DEGREES
from real_time_manim.vulkan_bind import MLWindow, Wait

class RemoveClearDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        sq = Square(color=GREEN, side_length=1.0, fill_opacity=0.6).shift(LEFT * 3.0)   #绿色方块
        spin = lambda m, dt: m.rotate(dt * 120 * DEGREES)   #命名保存：移除时要传同一个函数对象
        sq.add_updater(spin)   #挂上
        self.add(sq)   #进场景
        print("挂载后 updaters =", len(sq.get_updaters()))   #1
        win.play(Wait(0.6))   #转起来
        sq.remove_updater(spin)   #按同一个函数对象移除
        print("remove 后 updaters =", len(sq.get_updaters()))   #0
        sq.add_updater(lambda m, dt: m.shift(DOWN * dt))   #再挂一个匿名函数：每秒下落 1
        win.play(Wait(0.5))   #往下掉
        sq.clear_updaters()   #清空全部 updater（递归）
        print("clear 后 updaters =", len(sq.get_updaters()))   #0
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：绿方块先挂命名保存的 `spin` 转 0.6 秒（控制台 `挂载后 updaters = 1`）；`remove_updater(spin)` 传**同一个函数对象**把它摘掉，方块立刻停转（`0`）；再挂一个匿名函数让它匀速下落 0.5 秒；最后 `clear_updaters()` 全部清空，下落也停了（`0`）。

<video src="assets/RTM output/08-更新器-remove_clear.mp4" controls width="560"></video>

> 提醒：`remove_updater` 要的是**引用相等**的同一个函数——匿名函数 `lambda m, dt: ...` 没法再指认，想移除就先存变量。`clear_updaters(recursive=True)` 是递归清子对象的，想只清自己传 `recursive=False`。

### suspend_updating / resume_updating / update

```python
def suspend_updating(recursive: bool = True) -> Self
def resume_updating(recursive: bool = True) -> Self
def update(dt: float = 0, recursive: bool = True) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `recursive` | `bool` | `True` | 是否递归作用于子对象 |
| `dt` | `float` | `0` | 仅 `update`：传给时间型 updater 的秒数 |

> **返回**：自身。`suspend_updating` 暂停执行但**函数仍在列表里**；`resume_updating` 恢复时立即以 `dt=0` 跑一遍；`update(dt)` 手动触发一次——正常由渲染循环调用，只有 `Scene` 之外（交互脚本、单测）才需要；暂停期间 `update` 直接跳过。

#### 样例：转 → 停 → 又转 → 手动触发

旋转方块播放 0.5 秒后暂停（停转 0.5 秒），恢复后再转，最后手动 `update(dt=0)` 触发一次。

```python
from real_time_manim import Scene, Square, \
    RED, UP, DEGREES
from real_time_manim.vulkan_bind import MLWindow, Wait

class SuspendDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        sq = Square(color=RED, side_length=1.0, fill_opacity=0.6).shift(UP * 1.5)   #红色方块
        sq.add_updater(lambda m, dt: m.rotate(dt * 120 * DEGREES))   #每秒转 120°
        self.add(sq)   #进场景
        win.play(Wait(0.5))   #转起来
        sq.suspend_updating(recursive=True)   #暂停：函数还在列表里，只是不执行
        win.play(Wait(0.5))   #停转
        sq.resume_updating(recursive=True)   #恢复：立即以 dt=0 跑一遍
        win.play(Wait(0.3))   #又转起来
        sq.update(dt=0, recursive=True)   #手动触发一次（渲染循环之外才需要）
        win.play(Wait(0.3))   #进行 0.3s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：红色方块挂旋转 updater 后——第一段 `Wait` 里匀速转；`suspend_updating(recursive=True)` 之后的第二段 `Wait` 里完全停转（updater 还挂在列表里，只是不执行）；`resume_updating` 恢复，第三段又转起来；最后 `sq.update(dt=0, recursive=True)` 手动触发一次（`dt=0` 所以没有可见效果——这个 API 是给渲染循环之外的场景用的，视频里能看到的是它没有打断正常节奏）。

<video src="assets/RTM output/08-更新器-suspend.mp4" controls width="560"></video>

> 提醒：典型用法是**动画期间** `suspend_updating` 防止 updater 干扰插值，动画结束再 `resume_updating`。恢复时立即以 `dt=0` 跑一遍非时间型 updater，所以跟随标签会立刻归位。`update` 一般用不到——RTM 每帧自动驱动。

### always（属性）

```python
def always.method(*args, **kwargs) -> _UpdaterBuilder
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `*args`, `**kwargs` | `Any` | — | 直接传给目标方法的参数 |

> **返回**：`_UpdaterBuilder`（挂载即生效）。`t.always.next_to(sq, UP)` 等价于 `t.add_updater(lambda m: m.next_to(sq, UP), call_updater=True)`；链式的每个方法是**各自独立**的 updater。不要写 `mob.always.get_value(...)` 这类只读方法——参数只在挂载时求值一次，需要每帧重算的值请用 `add_updater`。

#### 样例：跟随标签

`tag.always.next_to(sq, UP, buff=0.3)` 一行挂好跟随——方块移动时标签全程吸附在它上方。

```python
from real_time_manim import Scene, Square, Text, \
    BLUE, YELLOW, UP, LEFT, RIGHT
from real_time_manim.vulkan_bind import MLWindow, Wait

class AlwaysDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        sq = Square(color=BLUE, side_length=1.2, fill_opacity=0.6).shift(LEFT * 3.0)   #蓝色方块
        self.add(sq)   #进场景
        tag = Text("tag", font_size=28, color=YELLOW)   #跟随标签
        tag.always.next_to(sq, UP, buff=0.3)   #语法糖：等价 add_updater(..., call_updater=True)
        self.add(tag)   #进场景
        win.play(sq.animate.shift(RIGHT * 2.5), run_time=0.8)   #标签全程跟随
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：一行 `tag.always.next_to(sq, UP, buff=0.3)` 就把「标签永远在方块正上方 0.3」挂成 updater（挂载瞬间先执行一次，所以一开始就在正确位置）；方块往右移动的 0.8 秒里，黄色的 `tag` 一路吸附跟随。这就是 `add_updater(lambda m: m.next_to(...), call_updater=True)` 的语法糖。

<video src="assets/RTM output/08-更新器-always.mp4" controls width="560"></video>

> 提醒：`.always.method(...)` 的参数**挂载时求值一次**——写 `t.always.next_to(sq, UP)` 没问题（`sq` 是引用、每次执行都会重读它的位置），但别指望它每帧重新计算参数表达式；需要每帧动态参数就老老实实 `add_updater(lambda m: m.next_to(target(), UP))`。它和模块级的 `always` 函数是两回事（见 [08b-更新器工具函数](08b-更新器工具函数.md)）。

### get_updaters / get_time_based_updaters / has_time_based_updater / match_updaters

```python
def get_updaters() -> list[_Updater]
def get_time_based_updaters() -> list[_TimeBasedUpdater]
def has_time_based_updater() -> bool
def match_updaters(mobject: Mobject) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `mobject` | `Mobject` | — | 仅 `match_updaters`：照搬其 updater 列表（只搬该对象自己的） |

> **返回**：前三个返回列表 / `bool`（调试神器），`match_updaters` 返回自身。

#### 样例：查询与照搬

方块挂旋转后打印三种查询结果；红点 `match_updaters(square)` 照搬后也转起来。

```python
from real_time_manim import Scene, Square, Dot, \
    GREEN, RED, RIGHT, DEGREES
from real_time_manim.vulkan_bind import MLWindow, Wait

class QueryMatchDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        sq = Square(color=GREEN, side_length=1.0, fill_opacity=0.6).shift(LEFT * 3.0)   #绿色方块
        spin = lambda m, dt: m.rotate(dt * 90 * DEGREES)   #命名保存
        sq.add_updater(spin)   #挂上
        self.add(sq)   #进场景
        print("get_updaters =", len(sq.get_updaters()))   #1
        print("get_time_based_updaters =", len(sq.get_time_based_updaters()))   #1
        print("has_time_based_updater =", sq.has_time_based_updater())   #True
        d2 = Dot(color=RED, radius=0.1).shift(RIGHT * 3.0)   #红点
        d2.match_updaters(sq)   #照搬 sq 的 updater 列表（只搬 sq 自己的）
        self.add(d2)   #进场景
        print("d2 updaters =", len(d2.get_updaters()))   #1
        win.play(Wait(0.8))   #两个都在转
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：绿方块挂上时间型 `spin` 后三种查询全过——`get_updaters` 列表长 1、`get_time_based_updaters` 长 1、`has_time_based_updater` 为 `True`；右侧红点一行 `match_updaters(sq)` 把方块的 updater 列表照搬过来（`d2 updaters = 1`），于是它也跟着匀速旋转——两个对象共用同一个函数对象，谁转得都正常。

<video src="assets/RTM output/08-更新器-query_match.mp4" controls width="560"></video>

> 提醒：`match_updaters` 只搬**对方自己的**列表（不递归子对象）；搬过来的是函数引用——同一个函数在两个对象上执行时各收到各自的 `mob`，互不串扰。调试「updater 到底挂没挂上」就靠这三兄弟打印。
