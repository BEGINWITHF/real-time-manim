# 摆放位置（进阶）

排列、网格、包裹与坐标精调——比 `next_to` 更批量化的摆放手段。以下方法均返回自身。

## 参数

### align_on_border

```python
def align_on_border(direction: Vector3DLike, buff: float = 0.5) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `direction` | 向量 | — | 指向边/角的方向，**不要求单位向量**。**能填** `UP` / `LEFT` 这类边方向（贴边）、`UL` / `DR` 这类对角方向（贴角） |
| `buff` | `float` | `0.5` | 留白。实际位移里减的是 `buff * direction`，方向不是单位向量时留白会按分量放大 |

> **返回**：自身。把自己的 `direction` 关键点对到 `sign(direction) × (frame_x_radius, frame_y_radius)`——`to_edge` / `to_corner`（见 [02-摆放位置](02-摆放位置.md)）就是它的两个封装。

#### 样例：`align_on_border` 贴边与贴角

红方块贴上边、蓝方块贴右下角，留白都是 0.4。

```python
from real_time_manim import Scene, Square, \
    RED, BLUE, UP, DR, FadeIn
from real_time_manim.vulkan_bind import MLWindow, Wait

class BorderDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        a = Square(color=RED, side_length=0.9)   #贴上边的方块
        b = Square(color=BLUE, side_length=0.9)   #贴右下角的方块
        a.align_on_border(UP, buff=0.4)   #关键点贴向上方边界，留白 0.4
        b.align_on_border(DR, buff=0.4)   #关键点贴向右下角
        self.add(a, b)   #进场景
        win.play(FadeIn(a), FadeIn(b), run_time=0.6)   #两个方块淡入
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：两个一样大的方块各贴各的位置——红方块 `direction=UP`，它的上边缘中点被挪到画面上边界内 0.4 处；蓝方块 `direction=DR`，右下角贴进右下角方向的边界。这就是 `to_edge` / `to_corner` 底层在做的事，只是这里方向一步到位、不拆成两个方法。

<video src="assets/RTM output/02b-摆放位置-进阶-border.mp4" controls width="560"></video>

> 提醒：`buff * direction` 这个实现细节意味着传非单位向量（比如 `UP * 2`）时留白会翻倍，方向向量只取符号用途的话记得归一化。日常直接用 `to_edge` / `to_corner` 更省心。

### set_coord / set_x / set_y / set_z

```python
def set_coord(value: float, dim: int, direction: Vector3DLike = ORIGIN) -> Self
def set_x(x: float, direction: Vector3DLike = ORIGIN) -> Self
def set_y(y: float, direction: Vector3DLike = ORIGIN) -> Self
def set_z(z: float, direction: Vector3DLike = ORIGIN) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `value` / `x` / `y` / `z` | `float` | — | 目标坐标（绝对值，不是增量） |
| `dim` | `int` | — | **只能填** `0`=x、`1`=y、`2`=z（仅 `set_coord`） |
| `direction` | 向量 | `ORIGIN` | 用哪个关键点对准该坐标：默认中心；`LEFT` 表示「左边缘的 x 设成这个值」 |

> **返回**：自身。`set_x` / `set_y` / `set_z` 就是 `set_coord` 的三个固定 `dim` 版本。只改一轴、另一轴原地不动，写 updater 时配合 `get_x` 很顺手。

#### 样例：`set_x` / `set_y` / `set_coord` 逐轴设坐标

方块分三步把 x 设为 -3、y 设为 1.5、再用 `set_coord` 把 x 设为 2.5；最后演示 `direction=LEFT` 只认左边缘，z 的改动打到控制台。

```python
from real_time_manim import Scene, Square, \
    BLUE, LEFT, FadeIn
from real_time_manim.vulkan_bind import MLWindow, Wait

class CoordsDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        sq = Square(color=BLUE, side_length=1.2, fill_opacity=0.6)   #蓝色方块
        self.add(sq)   #进场景
        win.play(sq.animate.set_x(-3.0), run_time=0.5)   #set_x：x 设为 -3，y 不动
        win.play(sq.animate.set_y(1.5), run_time=0.5)   #set_y：y 设为 1.5，x 不动
        win.play(sq.animate.set_coord(2.5, 0), run_time=0.5)   #set_coord：dim=0 即 x 设为 2.5
        sq.set_x(0.0, direction=LEFT)   #direction=LEFT：把左边缘的 x 设为 0（中心停在 0.6）
        sq.set_z(0.5)   #set_z：改 z 坐标，2D 画面看不出变化
        print("get_z =", sq.get_z())   #验证 z 的确改成了 0.5
        win.play(Wait(0.5))   #进行 0.5s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：一个蓝方块分三步被「设坐标」——`set_x(-3)` 只动 x、`set_y(1.5)` 只动 y、`set_coord(2.5, 0)` 与 `set_x(2.5)` 等价；然后 `set_x(0.0, direction=LEFT)` 改成把**左边缘**的 x 对准 0，方块中心因此停在 0.6 而不是 0。最后 `set_z(0.5)` 改 z 轴——2D 画面看不出差别，控制台打印 `get_z` 验证它确实生效。

<video src="assets/RTM output/02b-摆放位置-进阶-coords.mp4" controls width="560"></video>

> 提醒：这些是**绝对坐标**（`set_x(2)` = x 变成 2），与 `shift` 的相对位移别搞混。`direction` 让你能按边缘/角对准，做「左边缘贴参考线」这类排版很方便；不填就按中心。

### arrange

```python
def arrange(direction: Vector3DLike = RIGHT, buff: float = 0.25,
            center: bool = True, **kwargs: Any) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `direction` | 向量 | `RIGHT` | 排列方向。**能填** `RIGHT`（横排）、`DOWN`（竖排）等 |
| `buff` | `float` | `0.25` | 相邻间距 |
| `center` | `bool` | `True` | 排完是否整体移到原点；要保持原位传 `False` |
| `**kwargs` | `Any` | — | 透传给每个 `next_to`（如 `aligned_edge=`） |

> **返回**：自身。每个子对象依次 `next_to` 前一个，是批量排版的首选。

#### 样例：`arrange` 横竖排与 `center`

三个方块先横排居中，再动画改成竖排（间距 0.6），最后 `center=False` 排回横排但保持原位。

```python
from real_time_manim import Scene, VGroup, Square, \
    RED, BLUE, GREEN, RIGHT, DOWN, FadeIn
from real_time_manim.vulkan_bind import MLWindow, Wait

class ArrangeDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        row = VGroup(*[Square(color=c, side_length=0.8) for c in (RED, BLUE, GREEN)])   #三个方块
        row.arrange(RIGHT, buff=0.35)   #默认 center=True：整体居中
        self.add(row)   #进场景
        win.play(FadeIn(row), run_time=0.5)   #横排淡入
        win.play(row.animate.arrange(DOWN, buff=0.6), run_time=0.6)   #改成竖排，间距 0.6
        win.play(row.animate.arrange(RIGHT, buff=1.0, center=False), run_time=0.6)   #center=False：不整体回中
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：三个方块先按默认参数横排（`center=True`，整排移到画面正中）；然后播放 `arrange(DOWN, buff=0.6)`，三个方块一边互相靠拢一边改成竖排；最后 `arrange(RIGHT, buff=1.0, center=False)` 排回横排——注意 `center=False` 时整排**不回中**，就地展开，位置留在竖排时的地方。

<video src="assets/RTM output/02b-摆放位置-进阶-arrange.mp4" controls width="560"></video>

> 提醒：`arrange` 每次都从**当前**子对象顺序排——想固定顺序先 `sort` 或在构造时排好（见 [11b-低频其余API](11b-低频其余API.md)）。`**kwargs` 会透传给每一对相邻对象的 `next_to`，用 `aligned_edge=DOWN` 之类可以让整排按底边对齐。

### arrange_in_grid

```python
def arrange_in_grid(rows: int | None = None, cols: int | None = None,
                    buff: float | tuple[float, float] = 0.25,
                    cell_alignment: Vector3DLike = ORIGIN,
                    row_alignments: str | None = None,
                    col_alignments: str | None = None,
                    row_heights: Iterable[float | None] | None = None,
                    col_widths: Iterable[float | None] | None = None,
                    flow_order: str = "rd", **kwargs: Any) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `rows` / `cols` | `int` 或 `None` | `None` | 行数 / 列数；只给一个时另一个自动补足，都不给按接近正方形推断；`rows*cols` 装不下时抛 `ValueError` |
| `buff` | `float` 或 `(行, 列)` 元组 | `0.25` | 单元格间距；元组形式分别指定行、列间距 |
| `cell_alignment` | 向量 | `ORIGIN` | 元素在单元格内的对齐方式 |
| `row_alignments` | `str` 或 `None` | `None` | 每行对齐：`"u"`上 / `"c"`中 / `"d"`下 |
| `col_alignments` | `str` 或 `None` | `None` | 每列对齐：`"l"`左 / `"c"`中 / `"r"`右 |
| `row_heights` | 可迭代或 `None` | `None` | 每行高度，`None` 按该行最高者 |
| `col_widths` | 可迭代或 `None` | `None` | 每列宽度，`None` 按该列最宽者 |
| `flow_order` | `str` | `"rd"` | 填充顺序。**能填** `rd`/`dr`/`ld`/`dl`/`ru`/`ur`/`lu`/`ul`（r=右、l=左、d=下、u=上） |

> **返回**：自身。按「填充顺序」把子对象逐个放进网格单元，颜色顺序就是填充顺序。

#### 样例：`arrange_in_grid` 网格与 `flow_order`

六个不同颜色的方块先排成 2×3（行距 0.4、列距 0.8），再动画改成 3×2 并按列填充——颜色的去向就是 `flow_order` 的效果。

```python
from real_time_manim import Scene, VGroup, Square, \
    RED, ORANGE, YELLOW, GREEN, BLUE, PURPLE, FadeIn
from real_time_manim.vulkan_bind import MLWindow, Wait

class GridDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        colors = (RED, ORANGE, YELLOW, GREEN, BLUE, PURPLE)   #六个颜色 = 填充顺序
        cells = VGroup(*[Square(color=c, side_length=0.7) for c in colors])   #六个方块
        cells.arrange_in_grid(rows=2, cols=3, buff=(0.4, 0.8))   #2 行 3 列，行距 0.4、列距 0.8
        self.add(cells)   #进场景
        win.play(FadeIn(cells), run_time=0.6)   #网格淡入：红橙黄在第一行
        win.play(cells.animate.arrange_in_grid(rows=3, cols=2, flow_order="dr"), run_time=0.7)   #3 行 2 列、按列填充
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：六个颜色的方块按「红橙黄绿蓝紫」的顺序进组，第一次 `arrange_in_grid(rows=2, cols=3, buff=(0.4, 0.8))` 按默认 `flow_order="rd"` 行优先填充——红橙黄在第一行；第二次动画改成 `rows=3, cols=2, flow_order="dr"`，列优先、方向朝下，于是红绿一列、橙蓝一列、黄紫一列。想验证填充顺序，看颜色落在哪个格子最直观。

<video src="assets/RTM output/02b-摆放位置-进阶-grid.mp4" controls width="560"></video>

> 提醒：
>
> - `rows*cols` 必须装得下所有子对象，少了直接 `ValueError`。
> - 元素大小不一时，配合 `row_heights` / `col_widths` 或 `cell_alignment` 微调，否则按最大者撑格子。
> - `buff` 传元组时是「(行间距, 列间距)」，别按 `(列, 行)` 猜。

### surround / replace

```python
def surround(mobject: Mobject, dim_to_match: int = 0, stretch: bool = False,
             buff: float = 0.25) -> Self
def replace(mobject: Mobject, dim_to_match: int = 0, stretch: bool = False) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `mobject` | `Mobject` | — | 要包住 / 参照的对象 |
| `dim_to_match` | `int` | `0` | 按哪一维匹配：`0`宽、`1`高、`2`深 |
| `stretch` | `bool` | `False` | `False` 等比缩放到匹配；`True` 宽高分别拉伸（会变形） |
| `buff` | `float` | `0.25` | 包裹留白（仅 `surround`） |

> **返回**：自身。`surround` 让自己套住目标（同中心、按 `dim_to_match` 撑到目标尺寸+留白）；`replace` 让自己与目标同尺寸同中心（常做垫底衬）。

#### 样例：`surround` 外框与 `replace` 垫底

一段文字先被红框 `surround` 包住，再用蓝方块 `replace` 拉成同尺寸的半透明衬底。

```python
from real_time_manim import Scene, Rectangle, Text, \
    RED, BLUE, YELLOW
from real_time_manim.vulkan_bind import MLWindow, Wait

class SurroundReplaceDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        txt = Text("target", font_size=36, color=YELLOW)   #被包住的文字
        self.add(txt)   #进场景
        frame = Rectangle(color=RED)   #空矩形
        frame.surround(txt, buff=0.25)   #surround：按宽度包住文字，留白 0.25
        self.add(frame)   #进场景
        win.play(FadeIn(frame), run_time=0.5)   #外框淡入
        panel = Rectangle(width=1.0, height=1.0, color=BLUE, fill_opacity=0.4)   #小方块
        panel.replace(txt, stretch=True)   #replace：同中心、宽高分别拉伸到与文字一致
        self.add(panel)   #进场景
        win.play(FadeIn(panel), run_time=0.5)   #衬底淡入
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：黄色文字 `target` 进场景后，一个空的红矩形 `surround(txt, buff=0.25)` 变成套住文字的外框（默认按宽度匹配、等比缩放）；然后一个蓝色小方块 `replace(txt, stretch=True)`，宽高**分别**拉伸到与文字包围盒一致、中心重合，就成了文字背后的半透明衬底。两个方法都是「拿别人当尺子量自己」。

<video src="assets/RTM output/02b-摆放位置-进阶-surround_replace.mp4" controls width="560"></video>

> 提醒：
>
> - `stretch=False`（默认）时是等比缩放，`surround` 一个又扁又宽的文字会得到一个比文字高得多的框；想严丝合缝就 `stretch=True`（框会变形）或 `dim_to_match=0` 配 `buff` 调整。
> - `replace` 没有 `buff`，做垫底想大一圈就先 `replace` 再 `stretch_to_fit_width(width + 2*buff)`。

### put_start_and_end_on

```python
def put_start_and_end_on(start: Point3DLike, end: Point3DLike) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `start` | 点 | — | 目标起点坐标 |
| `end` | 点 | — | 目标终点坐标 |

> **返回**：自身。内部做「按长度缩放 + 按夹角旋转 + 平移」三连，把自己的起点终点**精确**钉到两点上。对闭合路径（起点=终点，如 `Circle`）只平移到 `start` 并发警告——没有方向可对。

#### 样例：`put_start_and_end_on` 钉住两端

一条水平线的两端被精确钉到两个红点上（缩放+旋转+平移一次完成）。

```python
from real_time_manim import Scene, Line, Dot, \
    BLUE, RED, UP, DOWN, LEFT, RIGHT
from real_time_manim.vulkan_bind import MLWindow, Wait

class PutEndsDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        line = Line(LEFT * 2, RIGHT * 2, color=BLUE)   #初始：长度 4 的水平线
        p1 = Dot(color=RED, radius=0.1).move_to(LEFT * 3 + DOWN * 1.5)   #目标起点
        p2 = Dot(color=RED, radius=0.1).move_to(RIGHT * 1 + UP * 2)   #目标终点
        self.add(line, p1, p2)   #进场景
        win.play(line.animate.put_start_and_end_on(p1.get_center(), p2.get_center()), run_time=0.7)   #缩放+旋转+平移，把两端钉到两点
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：一条长度 4 的水平蓝线，两个红点标记目标起点和终点。`put_start_and_end_on(p1, p2)` 一次调用完成三件事：按「目标长度/当前长度」等比缩放、绕起点旋转到目标方向、再平移让起点落到 p1——动画结束时线的两端不偏不倚钉在两个红点上。

<video src="assets/RTM output/02b-摆放位置-进阶-put_ends.mp4" controls width="560"></video>

> 提醒：顺序是「缩放绕起点 → 旋转绕起点 → 平移」，对**路径类**对象（`Line`、`Arrow`、`Arc`）最有效；`Circle` 这类闭合路径 `get_start()==get_end()`，只会平移并打印一条 `put_start_and_end_on has been called on a closed loop` 警告，想缩放圆用 `scale` / `surround`。

### shift_onto_screen / is_off_screen

```python
def shift_onto_screen(**kwargs: Any) -> Self
def is_off_screen() -> bool
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `**kwargs` | `Any` | — | 透传给内部的 `to_edge`（如 `buff=`）；`is_off_screen` 无参数 |

> **返回**：`shift_onto_screen` 返回自身，`is_off_screen` 返回 `bool`。前者只把**越出画面**的边拉回来（已在画面内则不动）；后者只在对象**完全**在画面外时为 `True`——露出一点都算 `False`。

#### 样例：拉回画面内外加判断

方块先挪到画面外很远（`is_off_screen=True`），`shift_onto_screen` 把它拉回左边缘内，再打印判断结果。

```python
from real_time_manim import Scene, Square, \
    RED, LEFT, FadeIn
from real_time_manim.vulkan_bind import MLWindow, Wait

class OffScreenDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        sq = Square(color=RED, side_length=1.2)   #红色方块
        sq.shift(LEFT * 12)   #挪到画面外很远
        print("is_off_screen =", sq.is_off_screen())   #True：完全在画面外
        self.add(sq)   #进场景
        win.play(sq.animate.shift_onto_screen(buff=0.5), run_time=0.7)   #拉回画面内，留白 0.5
        print("拉回后 is_off_screen =", sq.is_off_screen())   #False
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：红方块先被 `shift(LEFT * 12)` 甩出画面（此时打印 `is_off_screen = True`，画面里什么都看不到）；播放 `shift_onto_screen(buff=0.5)` 让它滑回画面内——这个方法只动越界的那些边，所以方块停在左边缘留白 0.5 处，而不是跳到正中；收回后再打印一次 `is_off_screen = False`。

> 提醒：
>
> - `shift_onto_screen` 不是「居中」也不是「完整可见」的保证——它按**边中点**逐边往回拉，超大对象拉回后仍可能四边都出画。
> - `is_off_screen` 的判断同样基于包围盒四边。
> - 它们参照的也是画面（`config`）而不是相机取景框。

### space_out_submobjects

```python
def space_out_submobjects(factor: float = 1.5, **kwargs: Any) -> Self
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `factor` | `float` | `1.5` | 间距倍数：`>1` 拉开、`<1` 收紧 |
| `**kwargs` | `Any` | — | 透传给内部的 `scale`（如 `about_point=` 指定拉开的基准点） |

> **返回**：自身。实现是「整组 `scale(factor)` + 每个子对象 `scale(1/factor)`」：子对象的**位置**被放大、**大小**被抵消，所以只改间距不改尺寸。

#### 样例：`space_out_submobjects` 拉开与收紧

三个几乎贴在一起的方块先拉开 1.8 倍（尺寸不变），再收回到 0.5 倍。

```python
from real_time_manim import Scene, VGroup, Square, \
    BLUE, RIGHT, FadeIn
from real_time_manim.vulkan_bind import MLWindow, Wait

class SpaceOutDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        g = VGroup(*[Square(color=BLUE, side_length=0.7) for _ in range(3)])   #三个方块
        g.arrange(RIGHT, buff=0.05)   #几乎贴在一起
        self.add(g)   #进场景
        win.play(g.animate.space_out_submobjects(1.8), run_time=0.6)   #factor>1：只拉间距，方块不变大
        win.play(g.animate.space_out_submobjects(0.5), run_time=0.6)   #factor<1：收紧
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：三个挨在一起的蓝色方块，先播放 `space_out_submobjects(1.8)`——以整组中心为基准，子对象的**位置**放大 1.8 倍而**尺寸**原样抵消，所以方块之间拉开、方块本身没变大；再播放 `factor=0.5` 反向收紧。想让某个角当拉开基准，加 `about_point=` 透传给内部的 `scale`。

<video src="assets/RTM output/02b-摆放位置-进阶-space_out.mp4" controls width="560"></video>

> 提醒：它的实现是先整组放大再把每个子对象缩回去，所以子对象之间的**相对布局**按 factor 等比缩放——横排拉开时竖排方向也会一起放大；另外子对象自身的缩放会被抵消的前提是两次缩放都以同一基准，中途挂了 `about_point` 之外的缩放参数时留意结果。
