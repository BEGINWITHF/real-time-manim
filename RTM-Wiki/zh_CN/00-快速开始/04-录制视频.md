# 录制视频

RTM 提供两个录制器：`fast_record_scene` 离线全速录制（默认无窗口），`record_scene` 对着可见的实时窗口录制。两者都包住场景的起止、录完自动清理临时 `media/`。

前提：`ffmpeg` 必须在 `PATH` 上。字幕与分段：`win.play(subcaption=...)` 录完已在 mp4 旁**自动产 `.srt`**（内存收集 + 落盘，导出函数 `real_time_manim.window.play.export_srt`）；要 `.srt`/分段这类命令行产物的另一半——`next_section` 分段视频——才确需 ffmpeg 手工切，见 [分段字幕与声音](../01-场景与相机/场景/04-分段字幕与声音.md)。

## 参数

### `record_scene`（实时、可见窗口）

```python
def record_scene(scene, out_path=None, *, fps=60, overwrite=True, cleanup=True, verbose=True) -> Dict[str, Any]:
```

| 参数          | 类型                                 | 默认值                               | 说明                                  |
| ----------- | ---------------------------------- | --------------------------------- | ----------------------------------- |
| `scene`     | `type \| 实例 \| Callable[[], None]` | —                                 | `Scene` 子类、`Scene` 实例或无参可调用对象       |
| `out_path`  | `str \| None`                      | `None` → `~/Downloads/output.mp4` | 目标 `.mp4`；一个场景开多个窗口时自动追加 `_partN`   |
| `fps`       | `int`                              | `60`（强制）                          | 后台线程抓取实时窗口的帧率                       |
| `overwrite` | `bool`                             | `True`                            | 为 `False` 时不覆盖已存在的 `out_path`       |
| `cleanup`   | `bool`                             | `True`（建议True）                    | 录完删除临时 manim `media/` 目录；`False` 保留 |
| `verbose`   | `bool`                             | `True`                            | 打印每个窗口的进度行                          |

> 注：录制帧率只**支持 `60`**（`SUPPORTED_FPS`）

### `fast_record_scene`（离线、默认无窗口）

```python
def fast_record_scene(scene, out_path=None, *, fps=60, hidden=True, count_only=False, segment=None, overwrite=True, cleanup=True, verbose=True, jobs=None) -> Dict[str, Any]:
```

| 参数           | 类型                                 | 默认值                               | 说明                                              |
| ------------ | ---------------------------------- | --------------------------------- | ----------------------------------------------- |
| `scene`      | `type \| 实例 \| Callable[[], None]` | —                                 | `Scene` 子类、`Scene` 实例或无参可调用对象                   |
| `out_path`   | `str \| None`                      | `None` → `~/Downloads/output.mp4` | 目标 `.mp4`（管道模式）；`segment` 模式下是目录                |
| `fps`        | `int`                              | `60`                              | 输出帧率；**只能填 60**（`enable_fast_record` 强制纠正并打印 `[rtm] forcing 60 fps`，`window/recording.py:142-145`） |
| `hidden`     | `bool`                             | `True`                            | 窗口隐藏且从不弹出，离线捕获不打扰桌面；`False` 可一边看一边录             |
| `count_only` | `bool`                             | `False`                           | 探测模式：只数帧，不捕获也不做 GPU 渲染                          |
| `segment`    | `tuple \| None`                    | `None`                            | `(start_frame, end_frame)`，把帧范围导出成 BMP 目录而非 MP4 |
| `overwrite`  | `bool`                             | `True`                            | 为 `False` 时不覆盖已有目标（`count_only` 时不适用）           |
| `cleanup`    | `bool`                             | `True`                            | 录完删除临时 manim `media/` 目录                        |
| `verbose`    | `bool`                             | `True`                            | 打印每个窗口的进度行                                      |
| `jobs`       | `int \| "auto" \| None`            | `None`（单进程）                       | 用几个 worker 进程并行分帧录制；`"auto"` 先探测再决定，`1` 强制单进程        |

#### `jobs`：多进程并行分帧（长场景提速）

时间可寻址的场景里**每一帧互不依赖**，所以可以把帧区间切给多个进程同时渲染：
第 i 个 worker 渲染自己那段连续帧到自己那个 mp4（编码参数与单进程**完全一致**），
最后用 `ffmpeg -f concat -c copy` 无损拼接。每帧成本随 worker 数下降。

* 默认 `jobs=None`：**单进程录制，不做任何探测**（探测要先起一个窗口 + Vulkan 设备
  才能数出总帧数，约 1.4 秒，短片段不值得）。
* `jobs="auto"`：先探测一次，只在划算时才分帧——场景 ≥ **240 帧**（60fps 下 4 秒）、
  能被子进程导入、且只开一个窗口，就分成 `min(4, CPU 核数-1)` 份。
* `jobs=4`：直接要 4 个 worker（仍会先探测一次总帧数与窗口数，不满足就退回单进程）。
* 需要能被别的进程导入的 **`Scene` 类**：实例、lambda、函数内定义的类都退回单进程。
  直接 `python 我的脚本.py` 运行的脚本必须有 `if __name__ == "__main__":` 保护，
  否则 worker 导入时会把它重新执行一遍（这种情况也会自动退回单进程）。
* 多窗口场景、`count_only`、`segment` 模式、`hidden=False` 都不并行。
* 每个 worker 用自己的 `media/` 目录（manim 的 `Text`/`Tex` SVG 缓存不是并发安全的）。
* `scene` 里的 `print()` 只会出现一次（父进程那一次），worker 的 stdout 被吞掉。
* 分帧录制走的是时间轴（`Timeline.render_at`）路径，**不跑每个动画的收尾钩子**
  （`finish()` / `clean_up_from_scene()`，例如 `FadeTransform` 的幽灵副本就是在那里清掉的）——
  依赖收尾逻辑的场景请用默认的 `jobs=None`。

> 实测（1920×1080@60，16 核）：15 秒场景单进程 **4.6–6.6 s（5.1–7.3 ms/帧）**（同会话
> 交替对比 ManimCE Cairo 的 12.8–13.9 s / 14.2–15.4 ms/帧，即快 1.9–2.8×）。四刀最关键：
> 录制期间窗口改用 `IMMEDIATE` 呈现（之前每帧有 6.9 ms 在等 vblank）、逐点坐标换算
> （每帧 2000+ 次）改成每个物体建一次投影器、仿射情形整段用 numpy 一次算完、以及
> 用点集直接算包围盒/中心（不再走 manim 逐点链表的 `get_center/get_bottom`）。
> Text 密集场景的 sync 从 11.2 ms 一路降到 2.5 ms（−78%）。
> `jobs=4` 在机器有余量时能到 1.4–2×，但共享同一个 iGPU 时会打不过单进程（实测），
> 所以默认不开、`auto` 也只在 ≥240 帧时才开。分帧录制走时间轴路径，不跑收尾钩子。

> **返回**：两者都返回 dict `{out_path, windows, files, with_audio}` —— `out_path` 输出路径、`windows` 交给各录制器的路径、`files` 实际落盘的文件、`with_audio` 是否带音轨（`record.py:225-230`）。

## 示例

```python
from real_time_manim import Scene, Square, BLUE
from real_time_manim.vulkan_bind import MLWindow, Create, Wait
from real_time_manim.record import fast_record_scene, record_scene

class MyScene(Scene):
    def construct(self):
        win = MLWindow(1280, 720)
        win.scene = self
        sq = Square(side_length=1.5, color=BLUE).set_fill(BLUE, 0.6)
        win.play(Create(sq), run_time=1.0)   # ManimCE 中等价于 self.play(Create(sq), run_time=1.0)
        win.play(Wait(0.5))
        win.close()

fast_record_scene(MyScene)                       # ~/Downloads/output.mp4
fast_record_scene(MyScene, "preview.mp4")        # 当前目录（也可给完整路径）
fast_record_scene(MyScene, fps=60, hidden=False) # 录制时同时显示窗口
fast_record_scene(MyScene, jobs=4)               # 4 个进程并行分帧（长场景更快）
record_scene(MyScene, "live.mp4", fps=60)         # 对着可见实时窗口录制（fps 只支持 60：填 30 会打印 “[rtm] forcing 60 fps” 后照渲 60）
```
