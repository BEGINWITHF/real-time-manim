# 任意帧预览（跳帧）

> 提醒：交互预览是 RTM 专属能力，窗口与控件条见下；回归测试 `tests/test_preview_spec.py`（20 项），跳帧耗时见下面的实测表。

弹出一个窗口，**默认什么也不播放**，窗口正下方停靠一条控件条（文本框或进度条）。在框里填入**任意一帧**回车，那一帧**立刻**出现在窗口里：不用预渲染整段视频，也不用从头重放到那一帧。

```bash
python -m real_time_manim.preview 1                    # run.py 里的 1 号 demo
python -m real_time_manim.preview examples.scenes:DemoCreate --at 120
```

## 为什么能"立刻"出帧

RTM 2.0 的渲染层是**时间可寻址**的：动画被定义成 `alpha`（进而时间 `t`）的纯函数，`Timeline.render_at(t)` 只求值一次并画一帧，代价与 `t` 无关（O(1)），而不是"从头播到第 t 帧"。预览模式把这件事接到交互上：

| 阶段 | 做什么 | 实测代价 |
| --- | --- | --- |
| 准备（一次性） | 跑一遍 `construct()`，**只排期不绘制**（`play` 变成记录动画语义，`FrameServer`） | 2.5s 场景 0.26s（热）/1.4–1.9s（冷）；6.3s 场景 0.30–0.43s |
| 每次 seek | `Timeline.render_at(t)` → `sync` → `tick` 一帧 | **1.3–7.5 ms**，与落点无关 |

也就是说：**没有任何预渲染**——你看到的第 0 帧就是窗口出现时现画的；之后的每一帧都是你输入时才画的。

> 一次 seek 重放的是**动画**状态；只靠自定义 updater / `TracedPath` 驱动的对象**向前步进精确、向后跳是近似**（把这类状态做成"可由 `t` 重放"是 RTM 2.0 计划里的 P3）。

## 控件条：输入框 / 进度条二选一

窗口下方那条控件条有两种外观，由 `controls=`（命令行 `--controls`）选：

| `controls` | 控件条 | 怎么跳帧 |
| --- | --- | --- |
| `"input"`（默认） | `[ 文本框 ] [Jump] [Save PNG] [Quit]` | 在文本框里填帧号/秒/步进，回车或点 `Jump` |
| `"slider"` | `[═════╪═════] [Save PNG] [Quit]` | 拖进度条（**拖动过程即实时抽帧**，连发的 seek 会自动合并成只画最新那一帧） |

两种模式窗口标题栏都实时显示 `frame 123/347   t=2.050s`。

```bash
python -m real_time_manim.preview 3 --controls slider
python -m real_time_manim.preview 3 --controls input
```

> 多个预览同时开：视频窗口是原生窗口、默认由系统摆位，可能**互相重叠**，用 `--pos X,Y`（或 `position=(x, y)`）把它们分开。
>
> 控件条会**始终贴着自己那个视频窗口**的下沿：你拖动视频窗口，控件条会跟着走。

## 输入语法（`input` 模式下在文本框里填）

| 输入 | 含义 |
| --- | --- |
| `120` / `120f` | **第 120 帧**（默认单位就是"帧"） |
| `1.5` / `1.5s` | 第 1.5 秒 |
| `+10` / `-1` | 从当前帧往前/往后跳 N 帧 |
| `s` | 把当前帧存成 PNG（默认 `frames/`，可用 `--out` 改） |
| `p` | 从当前帧起播（任何输入都会打断它） |
| `?` | 打印帮助 |
| `q` | 退出 |

越界会被夹到合法范围（`-999` → 第 0 帧）；看不懂的输入会打印提示而不是崩（例如 `cannot read '#' -- try 120, 2.5s, +1, s, q`）。

## 参数

```python
FramePreview(scene_cls, fps=60, out_dir="frames", use_bar=True,
             width=None, height=None, verbose=True,
             controls="input", position=None)
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `scene_cls` | `type \| 实例 \| Callable` | — | 要预览的场景（与 `fast_record_scene` 同一套写法） |
| `fps` | `int` | `60` | **帧号换算帧率**：`120` 表示第 120 帧，即 `t = 120 / fps` |
| `out_dir` | `str` | `"frames"` | `s` / `Save PNG` 存图的目录 |
| `use_bar` | `bool` | `True` | 为 `False` 时退回**终端输入**（同一套语法与队列协议，非 Windows 也能用） |
| `width` / `height` | `int \| None` | `None` | 窗口尺寸（RTM 只支持 1920×1080，会被强制纠正） |
| `verbose` | `bool` | `True` | 打印准备耗时与状态行 |
| `controls` | `str` | `"input"` | `"input"`（文本框）/ `"slider"`（进度条）；别名 `box`/`text`/`edit`、`bar`/`progress`/`scrub` 都认，写别的报 `ValueError` |
| `position` | `tuple \| None` | `None` | 视频窗口左上角 `(x, y)`，用于把多个预览分开；字符串形式 `"100,80"` 也接受 |

命令行等价开关：

| 开关 | 说明 |
| --- | --- |
| `scene`（位置参数） | demo 编号（`run.py` 的 `SCENES`）或 `module:Class` |
| `--at N` | 打开时先显示第 N 帧（默认 0） |
| `--fps N` | 帧号换算帧率（默认 60） |
| `--out DIR` | 存图目录（默认 `frames/`） |
| `--controls {input,slider}` | 控件条外观 |
| `--pos X,Y` | 视频窗口位置 |
| `--no-bar` | 只在终端里输入（不出控件条） |
| `--quiet` | 少打印 |

## 示例

```python
from real_time_manim import FramePreview          # 顶层懒导出
from examples.scenes import DemoCreate

FramePreview(DemoCreate).run()                     # 输入框模式
FramePreview(DemoCreate, controls="slider").run()  # 进度条模式
FramePreview(DemoCreate, use_bar=False).run()      # 终端输入
```

也可以只把它当"准备一次、随便取帧"的库来用（预览背后的 `FrameServer`）：

```python
from real_time_manim import FrameServer
fs = FrameServer(DemoCreate)      # 跑一遍 construct()，不绘制
fs.show_frame(2.05)               # 显示 t=2.05s（约 10 ms）
fs.save_frame(2.05, "f205.png")   # 顺手存成 PNG
fs.close()
```
