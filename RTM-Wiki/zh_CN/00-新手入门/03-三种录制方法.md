# 三种录制方法

real-time-manim **没有命令行**，出片靠 Python 里的函数调用。三种方法对应三种不同的「你会看到什么」：

| 方法 | 你会看到 | 产物 | 帧精确？ | 用途 |
| --- | --- | --- | --- | --- |
| `fast_record_scene` | 什么都不弹，控制台打进度 | mp4 | 是 | 批量出片、日常首选 |
| `record_scene` | 窗口弹出来把动画真实播一遍 | mp4 | 否（按墙钟） | 边渲边给人看 |
| `FramePreview` | 静止窗口 + 控制条，按帧跳着看 | 无（可存 PNG） | 是 | 调动画、找某一帧 |

下面逐个细说。

## 1. `fast_record_scene`——离线快速录制（看不到窗口）

窗口从头到尾**不弹出**，RTM 在后台逐帧读取 Vulkan 帧缓冲、直接喂给 ffmpeg，是最快、帧级精确的一条路。批量渲染、脚本出片都用它。

```python
from real_time_manim import *

class Demo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #把场景绑定给窗口
        circle = Circle(color=YELLOW).set_fill(YELLOW, 0.5)
        win.play(FadeIn(circle), run_time=1.0)   #淡入一个圆，时长1秒
        win.play(circle.animate.shift(RIGHT * 3), run_time=1.0)   #圆向右移
        win.play(Wait(0.5))   #等待0.5秒
        win.close()   #关闭窗口

fast_record_scene(Demo, "demo.mp4")#导出到项目目录下的 demo.mp4
```

**你会看到什么**：屏幕上什么都不弹；控制台按顺序打印

```
[rtm] forcing 1920x1080: RTM supports high quality only (asked for 960x540)
[FastRecord] Pipe: 1920x1080 @ 60 fps (bgra) -> .../demo.mp4
[record] window #1 -> .../demo.mp4
[FastRecord] Saved: .../demo.mp4 (150 frames, ... KB)
```

第一行是「尺寸被强制纠正为 1920×1080」的正常提示。`150 frames` = 2.5 秒动画 × 60 fps，**每一帧都精确落盘**，和 `win.play` 里的时长严格对应。

常用参数：`out_path`（不传默认 `~/Downloads/output.mp4`）、`hidden=False`（**边渲边弹窗**，而且照样帧级精确——想看又想要精确成片就用它）、`fps`（只能 60）。全部参数见 [RTM的录制与窗口参数](../01-场景与相机/配置/05-RTM的录制与窗口参数.md)。

## 2. `record_scene`——实时可见录制（能看到窗口）

窗口**真实弹出**，动画按真实时间播完，同时一个后台线程按墙钟抓屏合成 mp4。适合「渲染的同时给人看」的场合。

```python
from real_time_manim import *
from real_time_manim.record import record_scene

class Demo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #把场景绑定给窗口
        circle = Circle(color=YELLOW).set_fill(YELLOW, 0.5)
        win.play(FadeIn(circle), run_time=1.0)   #淡入一个圆，时长1秒
        win.play(circle.animate.shift(RIGHT * 3), run_time=1.0)   #圆向右移
        win.play(Wait(0.5))   #等待0.5秒
        win.close()   #关闭窗口

record_scene(Demo, "demo_live.mp4")#弹窗实时播放，同时录成 demo_live.mp4
```

**你会看到什么**：一个真的窗口弹出来把动画播完（`[Record] Recording to ... at 60 fps` 开始，`[Record] Captured N frames in X.Xs ... encoding ...` 收尾），录出来的 mp4 时长和真实播放一致。

> 提醒：这一路的帧数**不保证和离线渲染对齐**——它按墙钟走（含窗口启动/收尾时间），抓屏速度还受机器性能限制（实测抓屏约 6.5 帧/秒，成片按实际时长重排到 60fps：同一动画离线 114 帧 / 1.90s，实时 130 帧 / 2.17s）。想要帧级可复现的输出，用 `fast_record_scene`。

## 3. `FramePreview`——帧预览（跳帧，不出视频）

弹出一个**静止窗口 + 控制条**，默认什么都不播。你在控制条里输入任意帧号或时间，那一帧**立刻**出现在窗口里——不用从第 0 帧播过去，也不用预先渲染整条视频。

把第 1 节文件里的最后一行 `fast_record_scene(Demo, "demo.mp4")` 换成下面这段（`Demo` 场景不动），并在文件顶部加一行导入：

```python
from real_time_manim import FramePreview   #加在文件顶部

FramePreview(Demo).run()   #打开帧预览窗口（默认输入框模式）
```

**你会看到什么**：一个视频窗口，下面紧贴着一条控制条（输入框 + Jump / Save PNG / Quit 三个按钮），标题栏实时显示 `frame 0/150   t=0.000s`。输入框里可以敲：

| 输入 | 含义 |
| --- | --- |
| `120` / `120f` | 跳到第 120 帧 |
| `1.5` / `1.5s` | 跳到 1.5 秒 |
| `+10` / `-1` | 从当前帧前进/后退 N 帧 |
| `s` | 把当前帧存成 PNG（默认 `frames/` 目录） |
| `p` | 从当前帧开始播放（任意输入打断） |
| `q` | 退出 |

换成滑块模式则拖动滑块直接采样画面：`FramePreview(Demo, controls="slider").run()`。

想直接在脚本里抓某一帧存图（不开控制条），把它背后的 `FrameServer` 接在第 1 节的 `Demo` 场景上（同样在文件顶部加导入）：

```python
from real_time_manim import FrameServer   #加在文件顶部

fs = FrameServer(Demo)            #跑一遍 construct，什么都不画
fs.save_frame(1.5, "frame_1.5.png")#把 1.5 秒那一帧存成 PNG（约 10 ms，任意帧同样快）
fs.close()
```

---

**总结**：日常出片 `fast_record_scene`；要给人看渲染过程 `record_scene`（或 `fast_record_scene(hidden=False)`，弹窗但照样帧级精确）；调动画找某一帧用 `FramePreview` / `FrameServer`。
