# 画质与输出

manim 的 `config` 里管「画质与输出」的那批键——分辨率、帧率、格式、输出文件名……——在 RTM 里**基本都不接线**：RTM 不走 manim 渲染器，画质固定 1920×1080@60，帧率和输出文件名由录制函数的 `fps` / `out_path` 给。

整页真正接线的只有一个键：`background_color`（背景色），改了立竿见影，下面有出片。另有两条例外：`seed` 间接生效、`renderer` 反而别填。

## 参数

### `config` 画质与输出键（多数未接线；`seed` / `renderer` 见表内）

**作用**：这批键在 ManimCE 里控制分辨率、帧率、输出格式、文件名等；RTM 的画质与输出路径一概不读（写在脚本里没有画面效果）。例外只有两条：`seed` 经 `Scene.__init__` 间接固定随机数、`renderer` 被内嵌 ManimCE 读取（所以别填）。

下表逐条标了 RTM 的接线情况和「谁管这件事」。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `pixel_width` | `int` | `1920` | 不接线：输出宽度恒为 1920，由 `MLWindow(w, h)` 的尺寸决定（也只能填 1920×1080） |
| `pixel_height` | `int` | `1080` | 不接线：输出高度恒为 1080，同上 |
| `quality` | `str \| None` | `high_quality` | 不接线：**能填** `low_quality` / `medium_quality` / `high_quality` / `production_quality` / `fourk_quality`，但 RTM 只有 1920×1080@60 一档，填什么画面都不会变 |
| `frame_rate` | `float` | `60` | 不接线：帧率由 `fast_record_scene(fps=...)` 给，而且只支持 60，填别的会被强制纠正 |
| `format` | `str \| None` | `mp4` | 不接线：**能填** `png` / `gif` / `mp4` / `webm` / `mov`，RTM 只出 `mp4`；想要一帧帧的图用 `segment=(...)` 导 BMP |
| `output_file` | `str` | `""` | 不接线：输出文件名由 `fast_record_scene(out_path=...)` 给 |
| `background_color` | `ManimColor` | `BLACK` | **接线**：唯一有效的键，见下方小节 |
| `background_opacity` | `float` | `1` | 不接线：**能填** 0~1，但 RTM 下发的清屏色只有 RGB，输出永远不透明 |
| `transparent` | `bool` | `False` | 不接线：RTM 不出透明背景（就算把上一行填 0 也没用） |
| `save_last_frame` | `bool` | `False` | 不接线：只想要一帧图，用 `segment=(n, n+1)` 导 BMP |
| `write_to_movie` | `bool` | `True` | 不接线：不想写文件用 `count_only=True`（只数帧不落盘） |
| `write_all` | `bool` | `False` | 不接线：RTM 没有「渲文件里全部场景」的概念，想渲谁就在自己的脚本里逐个调用 |
| `save_sections` | `bool` | `False` | 不接线：想分段输出，就拆成多个场景分别录 |
| `zero_pad` | `int` | `4` | 不接线（PNG 序号补零位数；RTM 不出 PNG 序列） |
| `movie_file_extension` | `str` | `.mp4` | 不接线：恒为 `.mp4` |
| `from_animation_number` | `int` | `0` | 不接线：想从第几个动画开始渲，就把前面的 `win.play(...)` 注释掉 |
| `upto_animation_number` | `int` | `-1` | 不接线：同上，想渲到哪就把后面的 `win.play(...)` 去掉 |
| `preview` | `bool` | `False` | 不接线：想边渲边看，用 `fast_record_scene(hidden=False)` 或 `record_scene` |
| `show_in_file_browser` | `bool` | `False` | 不接线 |
| `verbosity` | `str` | `INFO` | 不接线：**能填** `DEBUG`/`INFO`/`WARNING`/`ERROR`/`CRITICAL`，但 RTM 的日志多少由 `fast_record_scene(verbose=...)` 管 |
| `progress_bar` | `str` | `display` | 不接线：**能填** `display`/`leave`/`none`，RTM 只打一行 `[FastRecord] Saved: ...` |
| `disable_caching` | `bool` | `False` | 不接线：RTM 没有片段缓存，每次都是全量渲染 |
| `flush_cache` | `bool` | `False` | 不接线（没有缓存可清） |
| `max_files_cached` | `int` | `100` | 不接线（同上） |
| `disable_caching_warning` | `bool` | `False` | 不接线 |
| `seed` | `int \| None` | `None` | **间接生效**：`Scene.__init__` 的 `random_seed` 默认值就是 `config.seed`（未显式传时取它，随后 `random.seed(...)` / `np.random.seed(...)`，`manim/scene/scene.py:180,223-224`）——`config.seed = 42` 同样能固定随机数。要固定随机数仍推荐显式 `random_seed=...`（见 [专用场景/01-MovingCameraScene](../专用场景/01-MovingCameraScene.md)） |
| `renderer` | `RendererType` | `cairo` | **别填**：RTM 的渲染器确实是 Vulkan、不会因此换成 OpenGL，**但内嵌 ManimCE 大量代码读它**（`Scene.__init__` 选 renderer/`mouse_point`、`VMobject` 类选择等），填 `opengl` 会改变甚至破坏行为，绝不是「没有任何效果」 |
| `dry_run` | `bool` | `False` | 不接线：只跑流程不写文件 = `count_only=True` |
| `save_pngs` | `bool` | `False` | 不接线（**已弃用**）：逐帧出图用 `segment=(...)` |
| `save_as_gif` | `bool` | `False` | 不接线（**已弃用**）：RTM 不出 GIF，自己拿 mp4 转 |

想改画质/输出，RTM 里对应的入口是这几个（详细参数见 [05-RTM的录制与窗口参数](05-RTM的录制与窗口参数.md)）：

| 想改什么 | RTM 里用 | 说明 |
| --- | --- | --- |
| 分辨率 | `MLWindow(w, h)` | 只能 1920×1080，传别的会被强制纠正并打印提示 |
| 帧率 | `fast_record_scene(fps=...)` | 只能 60，同上 |
| 输出文件名 | `fast_record_scene(out_path=...)` | 直接给文件路径，不走 `media_dir` 目录模板 |
| 背景色 | `self.camera.background_color` | 本页下方的样例 |
| 日志多少 | `fast_record_scene(verbose=...)` | `True` 打每窗口进度行，`False` 安静模式 |

这些键没有画面可言（除 `background_color` 外改了不出画面），所以本小节不出片；真正能看出来的只有背景色，见下一小节。

> 提醒：这批键写在脚本里**不会报错**，绝大多数**也不会生效**（例外两条：`seed` 会通过 `Scene.__init__` 的 `random_seed` 默认值间接固定随机数；`renderer` 反而**别填**，内嵌 ManimCE 会读它）。
>
> 最容易踩的坑是以为 `config.frame_rate = 30` 能出 30fps 的视频，实际 RTM 永远按 60fps 输出。想要非 60fps，只能渲完之后自己用 ffmpeg 转。
>
> 这些键在 ManimCE 里对应的命令行旗标见 [04-ManimCE命令行速查](04-ManimCE命令行速查.md)。

### `background_color` / `background_opacity`

```python
self.camera.background_color: ManimColor = BLACK   #清屏色：RTM 每帧读它，回退 config.background_color
self.camera.background_opacity: float = 1.0        #只记录在相机上；不透明 MP4 不会变淡（与 ManimCE 一致）
```

| 参数                   | 类型           | 默认值     | 说明                                                                                                                                        |
| -------------------- | ------------ | ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `background_color`   | `ManimColor` | `BLACK` | 接线：**能填**任何 manim 颜色——`"#12233a"`、`BLUE`、`"#e8e4d8"`……RTM 每帧从 `scene.camera.background_color` 读清屏色（没设就回退 `config.background_color`）下发给原生层 |
| `background_opacity` | `float`      | `1`     | 不接线：0~1 能读能写，但不改变画面——CE 只把它放进帧的 alpha 通道，不透明视频写出时 alpha 被丢掉，所以两引擎的成片都是满色（2026-10-19 起 RTM 与 CE 逐帧一致，见 [01-Camera](../相机/01-Camera.md)） |

#### 样例：`background_color`改动

同一个场景只改 `background_color` 一个值（外加为了让文字看得清的标签色），整屏底色就换掉了；两个片段拼在一起，深蓝、米白各一段。

```python
from real_time_manim import Scene, Square, Text, WHITE, UP, Create
from real_time_manim.vulkan_bind import MLWindow, Wait

class BackgroundColorDemo(Scene):
    BG = "#12233a"    #背景色：改成 “#e8e4d8” 再跑一次，整屏清屏色跟着换
    TXT = "#e8e4d8"   #标签颜色：浅色背景要换成深色才看得清

    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        self.camera.background_color = self.BG   #把 “background_color” 交给相机：清屏色就是它
        label = Text("background_color = %s" % self.BG, font_size=38,
                     color=self.TXT).to_edge(UP)   #上屏显示当前背景色
        sq = Square(side_length=2.0, color=WHITE).set_fill(WHITE, 0.8).set_stroke(width=4)   #白色方块：和背景拉开反差
        self.add(label)   #把标签放进场景
        win.play(Create(sq), run_time=0.8)   #画出白色方块
        win.play(sq.animate.scale(1.25), run_time=0.6)   #方块再放大一点
        win.play(Wait(0.5))   #进行 0.5s 的等待
        win.close()   #关闭 RTM 窗口


class BackgroundColorLight(BackgroundColorDemo):
    BG = "#e8e4d8"    #同一个场景，只把 “background_color” 换成米白
    TXT = "#12233a"   #标签换回深蓝
```

这段代码在做什么：开一个 RTM 窗口把场景绑上去，然后把 `self.camera.background_color` 设成深蓝——从这一帧起整屏的清屏色就是它。

接着上屏一行显示当前颜色的文字、画一个白色方块再放大一点，等 0.5 秒收工；`BackgroundColorLight` 子类只把 `BG` 换成米白（标签色换回深蓝），跑出来就是视频的第二段。

所以视频里能看到底色从深蓝整屏换成米白，而方块、文字、动画完全一样——变的只有清屏色这一个参数。

> 提醒：
>
> - `background_color` 是每帧都重读的，中途改也立刻生效（样例是开头设一次）。
> - 颜色字符串用 `"#rrggbb"` 十六进制最稳；文字/图形颜色和背景色记得拉开反差，样例里浅色背景就把标签换成了深蓝。
> - 别指望 `background_opacity` / `transparent`——RTM 的输出永远是不透明的 mp4。
