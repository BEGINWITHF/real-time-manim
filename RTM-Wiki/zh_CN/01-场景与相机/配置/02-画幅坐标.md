# 画幅坐标

画面的**逻辑坐标系**：默认高 8.0、宽 14.222…（= 8×16/9），中心在原点——`to_edge(UP)`、`[7.11, 0, 0]` 这些坐标都是在这个框里算的。这批键在 RTM 里是**布局参考值**：只读没问题（布局函数照用，两引擎画面一致），**写它们不受控**——RTM 的成像不保证跟 ManimCE 一样（原先"曲线不跟直线缩放"的 bug 已于 2026-10-16 修复，但两引擎读取时机仍不同，见下方样例）。想动镜头，用 `MovingCameraScene` 的 `self.camera.frame`（见 [专用场景/01-MovingCameraScene](../专用场景/01-MovingCameraScene.md)）。

## 参数

### `frame_width` / `frame_height` / `frame_x_radius` / `frame_y_radius`（画幅逻辑尺寸）

```python
config.frame_width: float = 14.222222   #画面逻辑宽；frame_x_radius = 它的一半
config.frame_height: float = 8.0        #画面逻辑高；frame_y_radius = 它的一半
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `frame_height` | `float` | `8.0` | 画面逻辑高度（manim 单位）。可读：`to_edge` / `next_to` 的边距就按它算。**不建议写**：CE 在相机构造时读走它、RTM 在成像换算时才读，两引擎画面不保证一致（见下面的样例；曲线/直线缩放不一致的 bug 已于 2026-10-16 修复） |
| `frame_width` | `float` | `14.222…`（= 8×16/9） | 画面逻辑宽度。可读；**不建议写**，同上 |
| `frame_y_radius` | `float` | `4.0` | `frame_height/2`。写它会联动改 `frame_height`，坑同上 |
| `frame_x_radius` | `float` | `7.111…` | `frame_width/2`。写它会联动改 `frame_width`，坑同上 |

#### 样例：默认画幅

在画面四角摆红点、中间放一个正方形和一个圆形：红点正好贴着画幅四角，正方形是方的、圆形是圆的——可见区域就是 14.222×8.0 的 16:9 框，坐标换算均匀不变形。

```python
from real_time_manim import (
    config,
    Scene, Square, Circle, Dot, Text, VGroup,
    WHITE, RED, GREEN, YELLOW,
    UP, DOWN, LEFT, RIGHT,
    FadeIn, Create,
)
from real_time_manim.vulkan_bind import MLWindow, Wait

class FrameLayoutDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        edge_x = 14.222222 / 2   #画面右边缘的 x：= “frame_width” / 2 = “frame_x_radius”
        edge_y = 8.0 / 2   #画面上边缘的 y：= “frame_height” / 2 = “frame_y_radius”
        label = Text("frame_width=14.222  frame_height=8.0", font_size=34,
                     color=WHITE).to_edge(UP, buff=0.3)   #上屏标注画幅尺寸
        corners = VGroup(*[
            Dot(color=RED, radius=0.1).move_to([sx * (edge_x - 0.25), sy * (edge_y - 0.25), 0])
            for sx in (-1, 1) for sy in (-1, 1)])   #四角各摆一个红点：画幅的四个角
        sq = Square(side_length=1.6, color=YELLOW).set_stroke(width=4).shift(LEFT * 1.2)   #正方形：画幅没变形的证据
        circ = Circle(radius=0.8, color=GREEN).shift(RIGHT * 1.2)   #圆形：同上
        self.add(label)   #把标签放进场景
        win.play(FadeIn(corners), run_time=0.6)   #四个角的红点淡入
        win.play(Create(sq), Create(circ), run_time=0.8)   #画出正方形和圆形
        win.play(Wait(0.5))   #进行 0.5s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：先按 `frame_width/2 ≈ 7.111`、`frame_height/2 = 4.0` 把可见区域的四个角算出来，各摆一个红点；再在中间画一个正方形和一个圆形。如果画幅比例不对，圆形会被拉成椭圆、正方形会变长方形；视频里两者都是标准形状、红点正好卡在画面四角，说明可见区域就是 14.222×8.0 的 16:9 框。顶上的文字把当前画幅尺寸打了出来。

<video src="assets/RTM output/02-画幅坐标-frame_layout.mp4" controls width="560"></video>

> 提醒：`edge_x = 14.222222 / 2` 这类常数写死在代码里最稳（它和 manim 的 `config` 默认值一致）；也可以直接读 `config.frame_x_radius`，默认值下结果一样。红点往里收了 0.25，正好露出边界又不出画——贴太紧会被画面边缘裁掉半个点。

#### 样例：改写画幅（两引擎行为不同）

同一份代码在 `__init__` 里把 `config.frame_x_radius` / `frame_y_radius` 改小一半（画幅 7.11×4.0）再摆同样的对象。**ManimCE 里视野真的缩小一倍**（相机构造时读走 config，画面放大铺满全屏）；**RTM 里直线与曲线同倍率缩放**（2026-10-16 修复曲线换算 bug；RTM 在成像换算时读同一个 `config` 键）——两侧最终一致，本条样例视频 2026-10-17 已重渲（`mean|diff|` 0.417、`frames>4.0: 0`）。

```python
from real_time_manim import (
    config,
    Scene, Square, Circle, Dot, Text, VGroup,
    WHITE, RED, GREEN, YELLOW,
    UP, DOWN, LEFT, RIGHT,
    FadeIn, Create,
)
from real_time_manim.vulkan_bind import MLWindow, Wait

class FrameOverrideDemo(Scene):
    def __init__(self, **kwargs):
        self._saved = (config.frame_x_radius, config.frame_y_radius)   #先记住默认的两个半径
        config.frame_x_radius = 3.555   #改写 “frame_x_radius”：画面宽变成 7.11
        config.frame_y_radius = 2.0     #改写 “frame_y_radius”：画面高变成 4.0
        super().__init__(**kwargs)   #相机在这里构造，CE 会读走改过的画幅

    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        label = Text("frame_x_radius=3.555  frame_y_radius=2.0", font_size=34,
                     color=WHITE).to_edge(UP, buff=0.3)   #上屏标注改写后的半径
        corners = VGroup(*[
            Dot(color=RED, radius=0.1).move_to([sx * (3.555 - 0.25), sy * (2.0 - 0.25), 0])
            for sx in (-1, 1) for sy in (-1, 1)])   #四角红点按改写后的画幅摆放
        sq = Square(side_length=1.6, color=YELLOW).set_stroke(width=4).shift(LEFT * 1.2)   #正方形：同上一份样例
        circ = Circle(radius=0.8, color=GREEN).shift(RIGHT * 1.2)   #圆形：同上一份样例
        self.add(label)   #把标签放进场景
        win.play(FadeIn(corners), run_time=0.6)   #四个角的红点淡入
        win.play(Create(sq), Create(circ), run_time=0.8)   #画出正方形和圆形
        win.play(Wait(0.5))   #进行 0.5s 的等待
        win.close()   #关闭 RTM 窗口
        config.frame_x_radius, config.frame_y_radius = self._saved   #还原默认值，别影响后面的样例
```

这段代码在做什么：和上一份样例摆的对象一模一样，只是先在 `__init__` 里把两个画幅半径改成 3.555 / 2.0（即画幅 7.11×4.0）再构造场景，最后还原。变化全在成像：ManimCE 读走新画幅，视野缩小一倍，同样的对象铺满全屏；RTM 在成像换算时读同一个 `config.frame_height`，直线与曲线同倍率缩放，最终画面与 ManimCE 一致（2026-10-16 修掉曲线/直线换算不一致、2026-10-17 重渲成片）。

<video src="assets/RTM output/02-画幅坐标-frame_override.mp4" controls width="560"></video>

> 提醒：**不要用改 `config` 画幅键的方式调画幅**——CE 和 RTM 各有一套理解（CE 相机构造时读走、RTM 成像换算时读），画面不保证一致。想要的画面远近请用 `MovingCameraScene` 的 `self.camera.frame.animate.set(width=...)`（[专用场景/01-MovingCameraScene](../专用场景/01-MovingCameraScene.md)），那条路两引擎一致。另外 `config` 是全局的：样例改完记得还原，否则后面的场景布局全部跟着变小。

### `top` / `bottom` / `left_side` / `right_side`（四边中点）、`aspect_ratio` / `frame_size`（只读）

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `top` / `bottom` | `Vector3D` | `[0, ±4, 0]` | 只读：上/下边中点坐标，摆标注时直接 `move_to(config.top)` |
| `left_side` / `right_side` | `Vector3D` | `[±7.111…, 0, 0]` | 只读：左/右边中点坐标，同上 |
| `aspect_ratio` | `float` | `1.777…` | 只读：像素宽高比 = 16/9。 不能写：RTM 的输出锁死 1920×1080，画幅永远 16:9 |
| `frame_size` | `tuple[int, int]` | `(1920, 1080)` | 只读：`(pixel_width, pixel_height)`，同上 |

#### 样例：四边中点

四个红点摆在 `top` / `bottom` / `left_side` / `right_side` 的位置并标上名字，一个白色游标沿它们走一圈——这四个坐标就是布局时最好用的锚点。

```python
from real_time_manim import (
    config,
    Scene, Square, Circle, Dot, Text, VGroup,
    WHITE, RED, GREEN, YELLOW,
    UP, DOWN, LEFT, RIGHT,
    FadeIn, Create,
)
from real_time_manim.vulkan_bind import MLWindow, Wait

class EdgePointsDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        edge_x = 14.222222 / 2   #画面右边缘的 x：“right_side” 的 x 坐标
        edge_y = 8.0 / 2   #画面上边缘的 y：“top” 的 y 坐标
        pts = VGroup(
            Dot(color=RED, radius=0.12).move_to([0, edge_y - 0.3, 0]),   #top：上边中点
            Dot(color=RED, radius=0.12).move_to([edge_x - 0.3, 0, 0]),   #right_side：右边中点
            Dot(color=RED, radius=0.12).move_to([0, -edge_y + 0.3, 0]),   #bottom：下边中点
            Dot(color=RED, radius=0.12).move_to([-edge_x + 0.3, 0, 0]),   #left_side：左边中点
        )
        names = VGroup(
            Text("top", font_size=28, color=YELLOW).next_to(pts[0], DOWN, buff=0.15),
            Text("right_side", font_size=28, color=YELLOW).next_to(pts[1], LEFT, buff=0.25),
            Text("bottom", font_size=28, color=YELLOW).next_to(pts[2], UP, buff=0.15),
            Text("left_side", font_size=28, color=YELLOW).next_to(pts[3], RIGHT, buff=0.25),
        )
        walker = Dot(color=WHITE, radius=0.18).move_to(pts[3])   #游标：从 “left_side” 出发
        self.add(pts, names, walker)   #把四个边点、四行名字和游标放进场景
        win.play(FadeIn(pts), FadeIn(names), run_time=0.6)   #四个边点和名字淡入
        win.play(walker.animate.move_to(pts[0]), run_time=0.5)   #游标走到 “top”
        win.play(walker.animate.move_to(pts[1]), run_time=0.5)   #游标走到 “right_side”
        win.play(walker.animate.move_to(pts[2]), run_time=0.5)   #游标走到 “bottom”
        win.play(Wait(0.5))   #进行 0.5s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：把四个红点分别摆到上、右、下、左四条边的中点上（坐标就是 `±frame_x_radius`、`±frame_y_radius`），旁边标好名字，然后让一个白色游标从 `left_side` 出发，依次走到 `top`、`right_side`、`bottom`。视频里能清楚看到这四个锚点贴着画面四边的正中——写布局时想贴边就用它们，或者直接 `move_to(config.top)`。

<video src="assets/RTM output/02-画幅坐标-edge_points.mp4" controls width="560"></video>

> 提醒：`top` / `bottom` / `left_side` / `right_side` 是算出来的只读属性，别试图给它们赋值；想把东西放边上，直接 `move_to(config.top)` 或 `to_edge(UP, buff=...)` 都行。`aspect_ratio` / `frame_size` 同样只读——想「改画幅」是改不动的，RTM 的像素输出恒为 1920×1080（强制纠正的演示见 [05-RTM的录制与窗口参数](05-RTM的录制与窗口参数.md) 的 `MLWindow` 样例）。

三个样例中 `frame_layout`、`edge_points` 逐像素一致（114 帧 / 1.90s、156 帧 / 2.60s）；`frame_override` 帧数一致（114 帧），两侧最终一致（曲线/直线换算不一致的 bug 于 2026-10-16 修复，成片 2026-10-17 重渲），对照见 `assets/README.md`。
