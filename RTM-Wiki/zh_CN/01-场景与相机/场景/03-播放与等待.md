# 播放与等待：play / wait 家族

动画的驱动核心。RTM 里播放统一写 `win.play(...)`，等待推荐写 `win.play(Wait(...))`。`self.wait` / `self.pause` / `self.wait_until` 这些 manim 写法也能用，但要先把 `self.play` 接到 `win.play` 上。

## 参数

### `Scene.play`（RTM 写法：`win.play(...)`）

```python
def play(self, *args: Animation | Mobject | _AnimationBuilder, subcaption: str | None = None, subcaption_duration: float | None = None, subcaption_offset: float = 0, **kwargs: Any) -> None:
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `*args` | `Animation \| Mobject \| _AnimationBuilder` | — | 要播放的动画，可多个（**并行**播放，总时长取最大 `run_time`）；`.animate...` 构造器会被自动解析 |
| `subcaption` | `str \| None` | `None` | 字幕文本：本次 play 的字幕从「play 开始时钟 + `subcaption_offset`」起记一条，录制结束自动在输出 mp4 旁落盘同名 `.srt`（见 [分段字幕与声音](04-分段字幕与声音.md)） |
| `subcaption_duration` | `float \| None` | `None` | 字幕显示时长（秒）；不传 = 本次 play 的实际时长 |
| `subcaption_offset` | `float` | `0` | 起始偏移（秒）：字幕时钟 = play 开始时刻 + 本偏移 |
| `**kwargs` | `Any` | — | 只认两个：`run_time=秒`（覆盖本条 play 里每个动画的时长）、`rate_func=函数`（覆盖速率曲线）；其余关键字会打印一条警告，不再被静默吞掉 |

> **返回**：无。RTM 中窗口方法是 `win.play(...)`；若你的场景方法内部会调 `self.play`（`move_camera`、`Write` 内部播放等），先写 `self.play = win.play` 接上。

#### 样例：`win.play` 的并行 / run_time / rate_func / `.animate`

一条 `play` 塞两个动画就是并行；`rate_func=linear` 匀速、不传则默认 smooth（两头慢中间快）。

```python
from real_time_manim import (
    Scene,
    Square, Circle, Text,
    YELLOW,
    UP, DOWN, LEFT, RIGHT,
    FadeIn, Write, linear,
)
from real_time_manim.vulkan_bind import MLWindow, Wait

class PlayDemo(Scene):
    RUN_TIME = 0.6   #动画时长：改成 1.2 看慢一倍的版本

    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 场景，绑定给名为 “win” 的 RTM 窗口
        a = Circle(color=RED).shift(LEFT * 2.5)   #左边的圆
        b = Square(color=GREEN).shift(RIGHT * 2.5)   #右边的方块
        self.add(a, b)   #两个对象上屏
        win.play(FadeIn(a), FadeIn(b), run_time=self.RUN_TIME)   #一条 play 塞多个动画 = 并行播放
        win.play(a.animate.shift(RIGHT * 1.2), run_time=self.RUN_TIME, rate_func=linear)   #“.animate” 构造器 + 线性速率
        win.play(a.animate.shift(LEFT * 1.2), run_time=self.RUN_TIME)   #默认 smooth 速率：两头慢中间快
        win.play(Write(Text("win.play", font_size=42, color=YELLOW).to_edge(DOWN)), run_time=self.RUN_TIME)   #Write 书写动画
        win.play(Wait(0.4))   #进行 0.4s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：先把圆和方块同时 `FadeIn`（一条 `play` 两个动画 = 并行，总时长就是 `RUN_TIME`）；然后用 `.animate` 让圆先匀速右移、再默认平滑地移回来，两段位移相同、速率曲线不同；最后 `Write` 书写一行字并等 0.4 秒收工。

把 `RUN_TIME` 改大，全部四段动画一起变慢。

<video src="assets/RTM output/03-播放与等待-play.mp4" controls width="560"></video>

> 提醒：`run_time` / `rate_func` 是这条 `play` 的公共参数，会覆盖**每个**动画各自的设置；想让两个动画不同时长就分开两条 `win.play`。`rate_func` 的可选曲线见 [速率函数](../../08-工具/02-速率函数.md)。

### 等待：`Wait` / `Scene.wait` / `Scene.pause` / `Scene.wait_until`

```python
# RTM 的 Wait（从 real_time_manim.vulkan_bind 导入），与 manim 的 Wait 同参
class Wait(Animation):
    def __init__(self, run_time=1.0, rate_func=None, stop_condition=None, frozen_frame=None, **kwargs):

# manim 的等待写法（内部都会转成一次播放，所以要先 self.play = win.play）
def wait(self, duration: float = DEFAULT_WAIT_TIME, stop_condition: Callable[[], bool] | None = None, frozen_frame: bool | None = None) -> None:
def pause(self, duration: float = DEFAULT_WAIT_TIME) -> None:
def wait_until(self, stop_condition: Callable[[], bool], max_time: float = 60) -> None:
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `duration` / `run_time` | `float` | `DEFAULT_WAIT_TIME`（=1.0） | 等待时长（秒），必须 > 0，写 0 或负数会像 manim 一样直接 `ValueError`（见 `validate_run_time`）。推荐写 `win.play(Wait(0.5))`（RTM 的 `Wait`）；`self.wait(0.5)` 等价 |
| `stop_condition` | `Callable[[], bool] \| None` | `None` | 每帧求值：每一帧绘制完成后调用一次条件函数，为真就提前结束等待（与 manim 的检查时机一致）。注意：只在正向播放（`play` / `wait`）时生效，随机访问抽帧（FrameServer）仍按完整时长渲染；条件函数抛异常时会优雅结束等待，而不是让整条 play 崩掉。与 `frozen_frame=True` 互斥，同时传会 `ValueError`（manim 同款报错） |
| `frozen_frame` | `bool \| None` | `None` | 控制等待期间画面是"冻结"还是"步进"：`True` = 整个等待 updaters 一律不驱动、画面定格（`self.pause` 就是它）；`False` = 场景里有 updater 也照常逐帧驱动；`None`（默认）自动判定——没有任何 updater、场景级更新函数或 `stop_condition` 时冻结，否则步进。与 manim 同一套规则 |
| `max_time` | `float` | `60` | 仅 `wait_until`：等待的时长上限；`stop_condition` 提前为真就不到这个时长 |

#### 样例：等待的四种写法

`win.play(Wait(...))`、`self.wait`、`self.pause` 三种写法效果一致（画面静止、时长如实）。`self.wait_until` 的条件每帧求值、一为真就提前结束——`lambda: True` 第一帧后就为真，所以等待只多渲染一帧。

```python
from real_time_manim import (
    Scene,
    Square, Text,
    BLUE, YELLOW,
    UP, DOWN,
    FadeIn,
)
from real_time_manim.vulkan_bind import MLWindow, Wait

class WaitDemo(Scene):
    FLAVOR = "play_wait"   #等待写法：四种口味，见下面的子类

    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 场景，绑定给名为 “win” 的 RTM 窗口
        self.play = win.play   #self.wait / self.pause / self.wait_until 内部都调 self.play，必须先接上
        tag = Text(self.FLAVOR, font_size=40, color=YELLOW).to_edge(UP)   #屏幕顶端显示当前写法
        sq = Square(color=BLUE).shift(DOWN)   #一个静态方块，方便看清等待时画面确实不动
        self.add(tag, sq)   #把标签和方块放进场景
        win.play(FadeIn(sq), run_time=0.3)   #先淡入 0.3s
        if self.FLAVOR == "play_wait":
            win.play(Wait(0.5))   #RTM 写法：win.play(Wait(秒))
        elif self.FLAVOR == "self_wait":
            self.wait(0.5)   #manim 写法：经 self.play 转发，等 0.5s
        elif self.FLAVOR == "self_pause":
            self.pause(0.3)   #冻结画面的暂停，等 0.3s
        else:
            self.wait_until(lambda: True, max_time=0.3)   #条件等待；条件第一帧后就为真，等待立即结束
        win.close()   #关闭 RTM 窗口


class WaitSelf(WaitDemo):
    FLAVOR = "self_wait"   #换成 self.wait


class WaitPause(WaitDemo):
    FLAVOR = "self_pause"   #换成 self.pause


class WaitUntil(WaitDemo):
    FLAVOR = "wait_until"   #换成 self.wait_until
```

这段代码在做什么：屏幕顶端显示当前用的是哪种等待写法，方块先淡入 0.3 秒，然后按 `FLAVOR` 走四种等待之一，期间画面完全静止。

视频四段依次是：

- `win.play(Wait(0.5))`（48 帧 = 18 帧淡入 + 30 帧等待）
- `self.wait(0.5)`（48 帧）
- `self.pause(0.3)`（36 帧）
- `self.wait_until(lambda: True, max_time=0.3)`（19 帧 = 18 帧淡入 + 1 帧等待）

最后一段的条件每帧求值、第一帧后就为真，所以 `max_time` 还剩很多时等待就已结束——这正是"等到某条件"的用法。

<video src="assets/RTM output/03-播放与等待-wait.mp4" controls width="560"></video>

> 提醒：三个坑。
>
> - ① `self.wait` / `self.pause` / `self.wait_until` 内部都会调 `self.play`，忘了 `self.play = win.play` 就会走进 manim 自己的渲染路径，画面不会出现在 RTM 窗口里。
> - ② 等待家族里只有 `win.play(Wait(...))` 用的是 RTM 的 `Wait`；`self.wait` 等用的是 manim 的 `Wait`，它自带一个空 `Mobject`，每等一次就会往 `scene.mobjects` 里塞一个空对象（画面无影响，但 `len(self.mobjects)` 计数会多）。
> - ③ `stop_condition` 只在正向播放时逐帧求值：随机访问抽帧（FrameServer / `render_at`）仍按完整时长渲染，别把它当随机访问安全的事件同步用。

### `Scene.add_updater` / `Scene.remove_updater`

```python
def add_updater(self, func: Callable[[float], None]) -> None:
def remove_updater(self, func: Callable[[float], None]) -> None:
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `func` | `Callable[[float], None]` | — | 每帧调用、参数为帧间隔 `dt` 的场景级更新函数；在所有 mobject 级 updater 跑完之后才跑（与 manim 的顺序一致）。`remove_updater` 把它从列表里摘掉，摘掉后立即停跑 |

mobject 级更新器（`mobject.add_updater`）同样每帧驱动，见 [更新器](../../02-Mobject通用/08-更新器.md)；两种写法可以混用。

#### 样例：场景级 vs mobject 级 updater

同一个 `wait` 里，蓝方块（mobject 级 updater）和红方块（场景级 updater）一起上移；摘掉两个 updater 后，第二段 `wait` 里两个都停住。

```python
from real_time_manim import (
    Scene,
    Square, Text,
    BLUE, RED,
    UP, DOWN, LEFT, RIGHT,
)
from real_time_manim.vulkan_bind import MLWindow, Wait

class UpdaterDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 场景，绑定给名为 “win” 的 RTM 窗口
        self.play = win.play   #场景方法内部会调 self.play，先接上
        mob = Square(color=BLUE).shift(LEFT * 3 + DOWN * 2)   #mobject 级 updater 驱动的方块
        via_scene = Square(color=RED).shift(RIGHT * 3 + DOWN * 2)   #场景级 updater 驱动的方块
        self.add(mob, via_scene)   #两个方块上屏
        self.add(Text("mobject.add_updater", font_size=24, color=BLUE).next_to(mob, UP))   #左边的说明
        self.add(Text("scene.add_updater", font_size=24, color=RED).next_to(via_scene, UP))   #右边的说明
        mob.add_updater(lambda m, dt: m.shift(UP * 0.03))   #mobject 级：RTM 每帧驱动，方块持续上移

        def scene_updater(dt):   #场景级：RTM 每帧驱动
            via_scene.shift(UP * 0.03)

        self.add_updater(scene_updater)   #把函数登记到场景上
        win.play(Wait(0.5))   #等 0.5s：蓝方块上移，红方块也上移
        self.remove_updater(scene_updater)   #摘掉场景级 updater
        mob.clear_updaters()   #摘掉 mobject 级 updater，蓝方块停住
        win.play(Wait(0.5))   #再等 0.5s：两个方块都不动
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：左右各放一个方块，左边挂 mobject 级 updater（每帧上移 0.03），右边把同样的逻辑用 `self.add_updater` 登记到场景上。

第一段 0.5 秒的等待里两个方块同步上移——两种 updater 现在都由 RTM 每帧驱动，且场景级在 mobject 级之后执行（与 manim 一致）。之后分别摘掉两个更新器，第二段等待里两个方块都静止。

<video src="assets/RTM output/03-播放与等待-updater.mp4" controls width="560"></video>

> 提醒：mobject 级 updater 的函数签名随便挑：`func()`、`func(m)`、`func(m, dt)` 都认（按参数个数分发）；嵌套在 `VGroup` 里的子对象也会被逐个驱动。
>
> 场景级 updater 固定收一个 `dt` 参数，想在 updater 里改别的对象也完全可以。

### `Scene.validate_run_time`

```python
@classmethod
def validate_run_time(cls, run_time: float, method: Callable[[Any], Any], parameter_name: str = "run_time") -> float:
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `run_time` | `float` | — | 待校验的时长（秒）；必须为正，否则直接 `ValueError` |
| `method` | `Callable` | — | 出错信息里显示的方法（如 `self.play`） |
| `parameter_name` | `str` | `"run_time"` | 出错信息里显示的参数名 |

返回校验后的 `float`（短于一帧的会被警告并夹到一帧长）。

`win.play` 现在**会**替你调它：`run_time` 写成 0 或负数直接抛 `ValueError`（manim 那套友好报错），短于一帧会警告并夹到一帧长；`wait` / `wait_until` 走的也是 `play`，同样受保护。自己写动画类需要校验时长时也可以手动调用它；不出视频。
