# 分段、字幕与声音

渲染产物控制三件套里，RTM 接了**声音**与**字幕**：`Scene.add_sound` 录制时会被捕获、混进 MP4 音轨；`win.play(..., subcaption=...)` 的字幕会在录制结束时落盘 `.srt`。

分段（`next_section`）和直接调 `Scene.add_subcaption` 仍依赖 manim 的文件写入器，RTM 不走那条路，调用不报错但**没有任何产物**。末尾附 RTM 下不可用的 OpenGL 交互调试 API。

## 参数

### `Scene.add_sound` 

```python
def add_sound(self, sound_file: str, time_offset: float = 0, gain: float | None = None, **kwargs: Any) -> None:
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `sound_file` | `str` | — | 音频文件路径（`.wav` / `.mp3`）。相对路径按**运行目录**解析，建议写绝对路径 |
| `time_offset` | `float` | `0` | 相对**当前时刻**再推迟多少秒开始播，可为负 |
| `gain` | `float \| None` | `None` | 音量增益，单位是 **dB**（不是倍数）：`6.0` 约响一倍，`-6` 轻一半，`None`/`0` 原音量 |
| `**kwargs` | `Any` | — | 透传：支持的（如 `gain_to_background` → pydub 的 `gain_during_overlay`）会被应用，不支持的关键字**显式打印告警**，不再被静默丢弃 |

在当前时刻（可加偏移）插入一段音轨。RTM 录制时由 `audio_track` 的 hook 捕获每次 `add_sound`，渲染结束后把所有声音混成一条音轨、用 ffmpeg 封进产出的 MP4（视频流不重编码）。

实时窗口本身不发声，声音只存在于录制产物里。

#### 样例：`Scene.add_sound`

两声"哔"：第一声在开场 0.5 秒后、加了 +6dB 增益；第二声在圆画完的瞬间、原音量作对照。听声音落点，再看圆上的 `Indicate` 打拍子。

```python
import os

from real_time_manim import Scene, Circle, ORANGE, Create, Indicate
from real_time_manim.vulkan_bind import MLWindow, Wait

class AddSoundDemo(Scene):
    GAIN = 6.0   #音量增益（dB）：改成 0 听原音量，改成 -6 听更轻

    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 场景，绑定给名为 “win” 的 RTM 窗口
        self.play = win.play   #场景方法内部会调 self.play，先接上
        beep = os.path.join(os.path.dirname(os.path.abspath(__file__)), "beep.wav")   #演示用的“哔”声
        self.add_sound(beep, time_offset=0.5, gain=self.GAIN)   #开场 0.5s 后“哔”一声（加大音量）
        dot = Circle(radius=0.9, color=ORANGE)   #一个圆
        self.add(dot)   #圆上屏
        win.play(Create(dot), run_time=1.0)   #用 1.0s 画出这个圆
        self.add_sound(beep, time_offset=0, gain=0)   #此刻（第 1.0s）再“哔”一声，不加增益作对照
        win.play(Indicate(dot), run_time=0.6)   #圆圈放大强调一下，给第二个声音打节拍
        win.play(Wait(0.6))   #进行 0.6s 的等待，留出声音的尾巴
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：一开场就登记第一声"哔"（`time_offset=0.5` 表示从现在起 0.5 秒后响，`gain=6.0` 明显更响），然后用 1 秒画一个圆。圆画完的瞬间登记第二声"哔"（不加增益），紧接着 `Indicate` 让圆放大缩小一下给这声打拍子，最后等 0.6 秒收尾。

录出来的 MP4 自带音轨，两声"哔"分别落在第 0.5 秒和第 1.0 秒。

<video src="assets/RTM output/04-分段字幕与声音-sound.mp4" controls width="560"></video>

> 提醒：`gain` 的单位是 **dB**，写 `1.5` 只是略微变响，想明显变响写 `6.0` 左右。
>
> RTM 的时间戳取的是"已录制时间轴的当前位置"（每次 `win.play` 结束后推进），所以把 `add_sound` 写在哪、声音就落在哪；实时预览窗口听不到声音，导出后用播放器听。
>
> 演示音 `beep.wav` 就放在 `assets/RTM code/beep.wav`，`add_sound` 的相对路径按**运行目录**解析，所以两版都从各自的 code 目录下跑。

### `Scene.next_section`

```python
def next_section(self, name: str = "unnamed", section_type: str = DefaultSectionType.NORMAL, skip_animations: bool = False) -> None:
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `name` | `str` | `"unnamed"` | 段名（非唯一），原用于输出文件名/索引 |
| `section_type` | `str` | `DefaultSectionType.NORMAL`（`"default.normal"`） | 供第三方（如演示工具）识别的类型标记 |
| `skip_animations` | `bool` | `False` | 跳过该段内所有动画的渲染 |

**调用无害、但没有任何产物**：分段输出依赖命令行的 `--save_sections` 与 `sections_dir`（manim 文件写入器把每段单独成片），而 RTM 没有 `manim` 命令行、也不跑文件写入器，所以 `next_section` 只是在内存里记了个段标记，最后什么都不落盘。

想把长视频分段，就按段写成多个场景、分别 `fast_record_scene` 出片，再用 ffmpeg 拼/切。不出视频。

### `Scene.add_subcaption` / `play(..., subcaption=...)`

```python
def add_subcaption(self, content: str, duration: float = 1, offset: float = 0) -> None:
```

| 参数         | 类型      | 默认值 | 说明        |
| ---------- | ------- | --- | --------- |
| `content`  | `str`   | —   | 字幕文本      |
| `duration` | `float` | `1` | 字幕显示时长（秒） |
| `offset`   | `float` | `0` | 起始时间偏移（秒） |

两条路都会落到同一份内存字幕表，并自动导出 `.srt`：

* `win.play(..., subcaption=..., subcaption_duration=..., subcaption_offset=...)`：按「本次 play 的开始时刻 + `subcaption_offset`」记时，`subcaption_duration` 不传就取该次 play 的实际时长。
* `self.add_subcaption(...)`（2026-10-18 起）：按**当前已录制时间轴的位置** + `offset` 记时，`duration` 不传默认 1 秒——与 manim 的语义一致。

录制结束（挂在 `audio_track.apply_sounds` 上）自动在输出 mp4 旁落盘同名 `.srt`（只在真有字幕时写文件，已端到端验证：直调 + play 两条 cue 的时间戳都正确落在 0.5s，而不是以前的 t=0）。不出视频。

### 交互调试：`interactive_embed` / `embed` / `set_key_function`

```python
def interactive_embed(self) -> None:
def embed(self) -> None:
def set_key_function(self, char: str, func: Callable[[], Any]) -> None:
```

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `char` | `str` | — | 按键字符 |
| `func` | `Callable[[], Any]` | — | 按下该键时执行的函数 |

均无返回。这一组是 OpenGL 渲染器的交互调试功能：

- `interactive_embed` 开 IPython shell + 实时预览
- `embed` 在预览窗口内嵌 IPython
- `set_key_function` 绑定单个按键

RTM 用自己的 Vulkan 窗口和 Timeline 出帧，没有这条交互链路，三个都不可用。想边看边调，就写小场景、`fast_record_scene` 秒渲出来看。不出视频。
