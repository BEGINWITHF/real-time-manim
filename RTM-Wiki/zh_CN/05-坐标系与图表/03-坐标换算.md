# 坐标换算（c2p / p2c / @ / add_coordinates）

坐标系**最容易踩坑**的专题：数据坐标 ⇄ 屏幕坐标。摆放一切元素（`Dot`、`Text`、`next_to`、`move_to`）都靠这组换算，手算比例尺是错误之源。

## x_range 与 x_length 的语义

| 写法 | 含义 |
| --- | --- |
| `x_range=[a, b, s]` | **数据范围** `[x_min, x_max]` 与**刻度步长** `s`；步长只决定画多少刻度/标签，不改变比例 |
| `x_length=L` | 该轴在屏幕上的**物理长度**（Manim 单位） |
| 比例尺 | `x_length / (b - a)`，每 1 数据单位对应这么多 Manim 单位 |
| 默认值 | `Axes()` → `x_range=[-7,7,1]`、`x_length≈12`、`y_range=[-4,4,1]`、`y_length≈6`；`NumberPlane()` → `x_length=None`（1 数据单位 = 1 Manim 单位） |
| 两元组 | `x_range=[0, 5]` 等价 `[0, 5, 1]` |
| 范围不含 0 | 自动把 0 点（或最近端点）移到中心，`c2p` 依旧按数据坐标算 |

## coords_to_point / c2p（数据 → 屏幕）

```python
def coords_to_point(self, *coords: float | Sequence[float] | np.ndarray) -> np.ndarray
```

别名 `c2p(*coords)`，亦可写 `ax @ (x, y)`。摆放一切元素的唯一正确途径。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `*coords` | `float \| Sequence[float] \| np.ndarray` | 必填 | 单点 `ax.c2p(1, 2)` / `ax.c2p([1, 2])`；批量 `ax.c2p([x0,x1,...], [y0,y1,...])`；3D 加第三个参数 |

> **返回**：`np.ndarray`，形状与输入对应（单点为 `(3,)` 场景坐标）。

## point_to_coords / p2c（屏幕 → 数据）

```python
def point_to_coords(self, point: Point3DLike) -> np.ndarray
```

`c2p` 的逆，常用于反推"这个点在图上是多少"。

| 参数 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `point` | `Point3DLike` | 必填 | 场景点，也可传点列表 `[RIGHT, [0,1,0]]` |

> **返回**：`np.ndarray`（如 `[4.0, 7.0]`）；传点列表则返回二维数组。

## 写法速查（@ 运算符，只留表格）

```python
ax.c2p(2, 1.5)          # 推荐
ax @ (2, 1.5)           # 同义（__matmul__）
ax.p2c(point)           # 反向，推荐
[1.0, 0.5, 0.0] @ ax    # 反向；只能传普通 list/tuple，
                        # np.ndarray 会被 numpy 抢先解释而报错 —— 请用 p2c
NumberLine() @ 3        # 数轴版本：数值 -> 点（即 n2p）
```

极坐标版本：`CoordinateSystem.polar_to_point(radius, azimuth)`（别名 `pr2pt`）、`point_to_polar(point)`（别名 `pt2pr`），内部就是 `c2p`/`p2c` 的三角变换，详见[极坐标与三维坐标系](07-极坐标与三维坐标系.md)。

#### 样例：`c2p`/`p2c`/`@`/批量换算

本样例演示三组用法：

- 绿点用 `c2p` 落位，并把 `p2c` 回读结果显示在旁边。
- 黄点演示 `@` 写法，并用 `assert` 做往返自检。
- 三个蓝点演示"传两个数组一次批量换算"。

```python
import numpy as np

from real_time_manim import Scene, Axes, Dot, Text, VGroup, \
    YELLOW, GREEN, BLUE, GREY_B, UP, DOWN, UR, DL, \
    Create, FadeIn, Write
from real_time_manim.vulkan_bind import MLWindow, Wait

class C2PDemo(Scene):
    def construct(self):
        win = MLWindow(960, 540)   #创建一个 RTM 窗口
        win.scene = self   #将名为 “self” 的 manim 窗口，绑定给名为 “win” 的 RTM 窗口
        title = Text("03-c2p-p2c", font_size=34, color=YELLOW).to_edge(UP)   #页面标题
        win.play(Write(title), run_time=0.5)   #写出标题

        ax = Axes(x_range=[-4, 4, 1], y_range=[-3, 3, 1],
                  x_length=8, y_length=5, tips=False)   #无箭头坐标系
        ax.add_coordinates()   #刻度数字
        labels = ax.get_axis_labels("x", "y")   #轴名称
        lab = Text("p = ax.c2p(2, 1.5)   coords = ax.p2c(p)",
                   font_size=26, color=GREY_B).to_edge(DOWN)   #方法说明标签
        win.play(Create(ax), FadeIn(labels), FadeIn(lab), run_time=0.8)   #坐标系与标签一起出场

        p = ax.c2p(2, 1.5)   #“c2p”：数据坐标 -> 屏幕坐标，摆放元素的唯一正确途径
        dot = Dot(p, color=GREEN)   #放在 c2p 结果上的绿点
        coords = ax.p2c(p)   #“p2c”：屏幕坐标 -> 数据坐标（c2p 的逆运算）
        readout = Text("p2c=(%.1f, %.1f)" % (coords[0], coords[1]),   #把回读结果显示在屏幕上
                       font_size=28, color=GREEN).next_to(dot, UR, buff=0.2)
        win.play(FadeIn(dot), FadeIn(readout), run_time=0.5)   #绿点与回读文字淡入
        win.play(Wait(0.6))   #停 0.6s 看回读结果

        q = ax @ (1, -2)   #“@” 写法：等价于 ax.c2p(1, -2)
        assert np.allclose(ax.p2c(q), [1, -2], atol=1e-6)   #往返换算自检：p2c(c2p(x)) == x
        dot2 = Dot(q, color=YELLOW)   #放在 @ 结果上的黄点
        tag2 = Text("ax @ (1,-2)", font_size=26, color=YELLOW).next_to(dot2, DL, buff=0.2)
        win.play(FadeIn(dot2), FadeIn(tag2), run_time=0.5)   #黄点与标签淡入

        batch = ax.c2p([-3, 0, 3], [-2, 0, 2])   #批量换算：传两个等长数组，一次算 3 个点
        dots3 = VGroup(*[Dot(pt, color=BLUE) for pt in batch])   #三个蓝点摆在对角线上
        win.play(FadeIn(dots3), run_time=0.4)   #三个蓝点淡入
        win.play(Wait(0.6))   #进行 0.6s 的等待
        win.close()   #关闭 RTM 窗口
```

这段代码在做什么：绿点由 `ax.c2p(2, 1.5)` 定位——无论坐标系比例如何，`c2p` 都给出正确屏幕坐标。`ax.p2c(p)` 再把屏幕坐标反算回 `(2.0, 1.5)` 显示出来，证明两者互逆。黄点用 `ax @ (1, -2)` 摆位，`assert np.allclose(ax.p2c(q), [1, -2])` 做了一次往返自检。最后 `ax.c2p([-3, 0, 3], [-2, 0, 2])` 传两个等长数组，一次换算出对角线上三个点——批量摆点时比循环快得多。

> 提醒：
>
> - 反向 `@`（`点 @ ax`）只能传普通 `list`/`tuple`——`np.ndarray` 会被 numpy 抢先解释成矩阵乘法而报错，反向统一用 `p2c`。
> - `c2p` 的返回值是 `np.ndarray`，别指望它是 `Point` mobject。

## add_coordinates 专题（只留表格）

`CoordinateSystem.add_coordinates(*axes_numbers, **kwargs)` 的写法速查（参数详解与样例见[02-Axes](02-Axes.md)）：

| 写法 | 效果 |
| --- | --- |
| `ax.add_coordinates()` | 全部轴用默认刻度数字 |
| `ax.add_coordinates(None, [0, 0.5, 1])` | x 轴保持默认，y 轴只显示指定数值 |
| `ax.add_coordinates(range(0, 9, 2), None)` | 只改 x 轴，y 轴不动 |
| `ax.add_coordinates({1: "Mon", 2: "Tue"}, None)` | dict 映射：数值 → 任意标签（`str` 自动变 `MathTex`） |
| `ax.add_coordinates(..., font_size=24)` | `**kwargs` 透传 `add_numbers`/`add_labels` |

三轴（`ThreeDAxes`）写法：`ax.add_coordinates(x_labels, None, z_labels)`；标签用 `ax.coordinate_labels` 取回。
