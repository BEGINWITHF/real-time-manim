# 2.0.0 — Time-addressable, manim-native animation layer

Status: **pre-work on branch `C-2.0.0-pre`** (legacy working pipeline remains on
`C-version-clean`; breaking changes are allowed here).

## Motivation

Two long-standing problems come from the same root:

1. **Maintainability.** The animation layer is a hand-written fork of manim
   (`real_time_manim/animations/`, ~2.7k LOC, 38 modules, its own
   `class Animation`). Every manim behaviour change has to be re-implemented by
   hand.
2. **No random access.** The renderer advances animations by wall-clock time and
   mutates mobjects in place, so reaching frame *N* requires replaying `0..N`.
   Scrubbing / "give me frame *t* instantly" is impossible.

## Key finding (verified)

**manim's own animations are pure functions of `alpha`.** Probe
(`_purity_probe.py`, GPU-free) evaluated each animation forward, jumped, and
returned to the same alpha in a different order; every state was identical:

```
FadeIn/FadeOut/Transform/ReplacementTransform/Create/DrawBorderThenFill/
Write/GrowFromCenter/SpinInFromNothing/Rotate/Rotating/FadeTransform
  back-to-alpha = True   order-independent = True
```

`Animation.interpolate(alpha)` recomputes the mobject from the start/target
copies captured in `begin()`; it does not accumulate. Therefore:

- we do **not** need our own animation classes — use `manim.animation.*`;
- evaluating an arbitrary `alpha` (hence arbitrary time `t`) is O(1).

GPU check (`_poc_seek_manim.py`) drove manim's `Transform` + `FadeIn` through our
renderer via `Timeline`: seek cost **2–4 ms, flat vs t** (one-off warm-up on the
2nd call), and seek frames matched sequential `play()` frames to ~1–6/255 mean
difference (h264 compression + sub-frame timing).

## Architecture

```
pristine baseline (mobjects at t = 0)
        │
        ▼
   evaluate(t):  for each active animation, set mobjects to their state at t
                 (manim:  anim.interpolate(alpha);  alpha = rate_func(t/run_time))
        │
        ▼
   renderer draws the frame  (MLWindow.sync)
```

- `play(...)` == `for t in 0, dt, 2dt, …: render_at(t)` (forward playback).
- `seek(t)` / `render_at(t)` == evaluate once at `t` and draw. O(1).
- `Timeline` (this branch, `real_time_manim/timeline.py`) is the first cut of
  this API; it is additive and does not touch `play` yet.

## Phases

- **P0 — feasibility. ✅** Purity probe + GPU seek check (done on this branch).
- **P1 — `Timeline` API.** `prepare(*animations)` (begin once) + `render_at(t)` /
  `seek(t)`. Drives **manim-native** animations. *(in progress)*
- **P2 — retire the fork.** Delete `real_time_manim/animations/*`; route
  `MLWindow.play` through the timeline; keep only renderer-level hooks that
  genuinely need per-frame drawing (text Write outline, Create progress) as pure
  functions of `alpha`.
- **P3 — stateful cases.** Give updaters / `TracedPath` / `DissipatingPath` /
  `Homotopy` / speed-modifiers a time-replayable definition (evaluate from a
  recorded function of `t`, not accumulated `dt`).
- **P4 — timelines & scheduling.** Per-animation start offsets, `AnimationGroup`
  lag ratios, `Succession`, so the whole scene is one `evaluate(t)`.
- **P5 — seek-driven playback.** `play` becomes increasing `t`; scrubbing, loop,
  reverse and export-a-range fall out for free.

## Acceptance criteria

- `seek(t)` cost independent of `t` (flat, O(1)) for all non-stateful anims.
- `seek(t)` frames == sequential frames at the same `t` (within compression
  tolerance).
- No hand-written animation class remains for behaviours manim already provides.
- All 82 demos render identically-or-better through the new pipeline on
  `C-version-clean` parity.
